# Shared daemon client, checkpoint 1

`milagre-daemon-client` is the backend-owned protocol-v1 client boundary agreed with the GPUI workstream in Chat #11899. It is independent of Tauri, GPUI and the caller's async runtime. This checkpoint implements the protocol engine and tests it with private Unix socket pairs. **No public launcher or endpoint constructor exists. It is not ready to connect a GPUI app to the fixture daemon.** No installed app or runtime imports this crate yet.

## Authority and next launcher gate

`FixtureGuard::endpoint()` is the only public endpoint-minting method. Both types have private fields and the crate has no public way to construct a guard. Tests construct synthetic authority inside `cfg(test)` only. There is no arbitrary executable, profile, socket, stream, environment or connector callback API, ambient discovery, Node fallback or daemon restart.

The next checkpoint must extract and test the exact owned-child launcher from `rust-desktop/src/fixture_launch.rs`: fixed sibling executable, private generated profile, bounded bootstrap receipt, child PID and peer verification, pinned directory/socket identities, retained child/stdin/profile ownership, acknowledged stop and confirmed reap, and bounded failure/drop handling. The future guard must own those resources, not merely a path or this checkpoint's diagnostic PID. Unknown ownership must never authorize signalling or profile removal. No child-cleanup guarantee is claimed here because this crate spawns no child.

An endpoint and the connection worker retain the same authority `Arc`. Reconnect is explicit: the caller retains the guard, obtains another endpoint and calls `Client::connect` again. It then explicitly reopens views, reads a snapshot, applies it and acknowledges it. There is no automatic reconnect, recovery, retry or replay. Multiple readers do not create another writer.

## Facade

All async methods use an internal standard-library I/O thread and executor-independent one-shot futures. A caller can use a GPUI executor, Tauri executor or `futures::executor::block_on`; no caller-thread Tokio runtime is required.

| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Client::connect(endpoint, options)`                       | Returns `(Client, Hello { wire, capabilities, owner }, Notifications)` after `daemon:status`. Protocol 1, expected owner PID, `closing: false`, string capability/method lists and both paging capabilities are required. Status metadata is diagnostic, never authority. |
| `project_current()`                                        | `project:current([])`; preserves the Project body and checks the generated Project path.                                                                                                                                                                                  |
| `project_read(path, with_state)`                           | `project:read([path, {state: bool}])`.                                                                                                                                                                                                                                    |
| `state_read(scope)`                                        | `state:read([scope])`, returning actual `state`, `version` and `epoch`.                                                                                                                                                                                                   |
| `chat_runs()`                                              | Global `chat:runs([])`, returning `{runs, seq}`. Run sequence is distinct from global wire sequence.                                                                                                                                                                      |
| `chat_messages(scope, numeric_id, {before, turns, limit})` | `chat:messages([scope, numeric_id, options])`; absent options stay absent. IDs/options must be JSON-safe unsigned integers. Returns the actual raw body and metadata. No cursor fields are invented.                                                                      |
| `open_view(path)`                                          | Explicit `project:open([path])`. It may recover or persist owner state. It is not a mutation-free read.                                                                                                                                                                   |
| `runtime_snapshot()`                                       | Captures and assembles `daemon:snapshot([{paged:true}])` plus `daemon:snapshot-page`. Returns `RuntimeSnapshot {body, event_seq}` with a private receipt.                                                                                                                 |
| `accept_snapshot(&snapshot)`                               | Local acknowledgment only, after the caller applies the snapshot. No RPC.                                                                                                                                                                                                 |
| `disconnect()`                                             | Closes this connection. Never stops the fixture owner.                                                                                                                                                                                                                    |

Only the exact generated Project scope is admitted. There is no raw RPC or Chat/content mutation API. Omitted, malformed, unsupported and foreign inputs fail visibly. Unknown fields in successful raw bodies and remote errors are preserved through `serde_json::Value` for version 0.1. Lossless JavaScript lone-surrogate JSON requires a separate boundary decision; this serde-based client rejects such frames rather than substituting characters.

## Ordering, resync and failures

`Notifications` is one ordered consumer of `Notice::Event {wire_seq, scope: Option<String>, channel, payload}` and one terminal `Notice::Closed(error)`. Wire sequence must increase on a connection, but gaps are allowed. Events are held from handshake and whenever snapshot capture starts. Starting another snapshot also holds already queued, unread events.

`runtime_snapshot()` validates the manifest and body watermark. It does not release events. `accept_snapshot` requires the exact connection and latest capture generation, refuses foreign, altered-watermark and stale receipts, and prevents accepted watermarks from regressing. Accepting the same current receipt twice is a no-op. Equal watermarks across successive captures are valid when the daemon emitted no event. It discards held events at or below the accepted global watermark and releases later events in arrival order. Events arriving subsequently at or below the accepted watermark are also discarded. A higher run `seq` never affects this barrier. Concurrent captures serialize; a later capture invalidates every earlier receipt, including an earlier accepted one. Hold overflow produces one terminal Closed notice; it never silently drops events above the watermark while keeping the connection usable.

Result paging (`result-pages-v1`) is internal and accepts the wire's positive safe numeric or nonempty string page IDs. Snapshot paging (`snapshot-pages-v1`) is separate. Page count, aggregate bytes, JSON, page identity and snapshot watermark mismatches fail without a partial result. The whole operation, including queue wait and pages, shares one deadline. Once the original request returns a page manifest, even a later page timeout before its own write reports `submitted: true`. A timed-out submitted request may still have executed; its later response is ignored and nothing is retried.

Errors preserve `Remote {code, message, payload}`. Local cases include `Disconnected`, `Busy`, `TimedOut {submitted}`, `Capability`, `Protocol`, `InvalidScope`, `StaleSnapshot` and `StateTooLarge {hydration}`. `Cancelled` is reserved for a future explicit local cancellation handle; dropping a future provides no result and only abandons its local wait. It does not free an admitted request early, cancel owner work, send a nonexistent cancel RPC, or trigger replay. Dropping an unpolled async call admits nothing.

Automatic deferred hydration of oversized Project events is not implemented in this checkpoint. A `stateTooLarge` event closes with `StateTooLarge` carrying its scope and required `project:read`; it never publishes a fabricated empty state. Reconnect and snapshot resync remain explicit. State patches, reduced Chat payload negotiation, computers, Links, remote endpoints and production authentication are not claimed. Existing Tauri transport has broader behavior and has not been replaced.

## Bounds and worker lifetime

Defaults are at most 32 accepted operations (queued plus active), 16 MiB per wire frame, 1,024 queued/held events and 16 MiB serialized event bytes, 1,024 pages and 128 MiB assembled result bytes, and a 30-second operation deadline. Options may only reduce these bounds. Admission credit releases before reply publication, including rejection; a caller awakened by completion can immediately use the returned slot. This first engine serializes wire operations; it is not yet the Tauri transport's concurrent RPC multiplexer. Notification bytes measure serialized payload size, not exact heap allocation or process RSS. One bounded terminal error slot is additional to the event queue. Overflow closes the connection; an already released prefix remains ordered, while events held behind an unaccepted snapshot are discarded.

The socket worker owns no writer or child. Dropping the last Client sets stop and shuts down its exact socket without blocking the caller on a join. The worker retains authority until its reads/writes finish and its loop exits. I/O uses bounded timeouts; OS scheduling and a future launcher connector need their own lifetime proof. The worker is not a replacement for the retained-child supervisor. A dropped connection attempt also drops the eventual Client result and closes that socket. No background request or reconnect loop survives through a public discovery service.

## Validation and remaining work

Run `cargo test --offline --locked`, `cargo clippy --offline --locked --all-targets -- -D warnings`, `cargo fmt --check` in this crate. There are 25 tests and three compile-fail doctests. Tests use only synthetic status and Unix-pair frames, with server assertions on the exact requests. They cover read shapes, result/snapshot pages, explicit barrier acceptance, foreign/stale receipts and repeated acceptance, run/wire sequence separation, dropped waits, bounded admission, publish-after-credit-release, operation-level page timeout accounting, late response handling, structured remote refusal, negotiation, overflow, visible hydration refusal, exact frame size and fragmented UTF-8, explicit reconnect, abandoned connection attempts and last-client cleanup. Compile-fail examples pin the absent path/socket constructors and private snapshot receipt.

Remaining gates: real owned-child launcher and cleanup; a real `app-fixture` daemon integration run; automatic oversized-state hydration; measured concurrent multiplexing; shared adoption by Tauri and the off-by-default GPUI adapter. GPUI owns presentation DTO mapping and reducers, not endpoint authority. Scripted send/approval/interrupt needs a separate write capability. Design/Artifact authoring follows the native content gate. None of those later stages is completed by this crate.
