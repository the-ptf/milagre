# Shared daemon client, owned-fixture checkpoint

`milagre-daemon-client` is the backend-owned protocol-v1 client boundary agreed with the GPUI workstream in Chat #11899. It is independent of Tauri, GPUI and the caller's async runtime. This checkpoint adds an exact owned-child launcher to the Unix-pair-tested protocol engine. Real `app-fixture` reads, paging, reconnect and lifecycle checks run separately from the default test suite. **It is not production authority or a complete GPUI adapter.** No installed app or runtime imports this crate yet.

## Authority and owned-child launcher

`FixtureGuard::launch()` is the only public constructor. It canonicalizes the current executable and launches only its fixed sibling `app-fixture`, without arguments. The sibling and parent must be owned by the current user, non-symlinks and not writable by group or others; the executable is a regular, executable, single-link file. Held descriptors and path identities are checked before spawn and again before admission. This is a cooperative same-user launch boundary, not executable signing or a sandbox against a malicious same-user process racing path checks.

The lifecycle worker creates a private mode-0700 `/tmp/milagre-client-launch-*` root, supplies its own HOME, XDG config/cache, TMPDIR, fixed system PATH and locale with `env_clear()`, and keeps the exact `Child` plus stdin. The daemon creates and owns its separate disposable profile. The launcher reads at most 4,096 bootstrap bytes in five seconds, validates the closed receipt schema, version, exact child PID, UID, fixed scripted/gated actor metadata, canonical generated paths and all four receipt identities. The socket must equal the protocol's SHA-256-derived path. Before and after every connection it validates pinned profile, Project, socket-directory and socket identities. macOS `getpeereid` and `LOCAL_PEERPID` must identify the same user and exact retained child. Other platforms cannot obtain public fixture authority.

`FixtureGuard::endpoint()` mints an opaque connection grant; `FixtureInfo` paths and PID are diagnostics only. There is no arbitrary executable, profile, socket, stream, environment or connector callback API, ambient discovery, Node fallback or daemon restart. Synthetic connector authority exists only inside `cfg(test)`. No copied production profile or credential is read.

An endpoint and its connection worker retain the same authority `Arc`. Reconnect is explicit: retain the guard, obtain another endpoint, connect, reopen views, apply a fresh snapshot and acknowledge it. There is no automatic reconnect, recovery, retry or replay. Multiple readers do not create another writer. Dropping one Client closes only its socket; it does not stop a guard-owned fixture.

### Shutdown and uncertain ownership

`FixtureGuard::shutdown()` seals new connections and asks the exact verified endpoint for `daemon:stop`. Its deadline is three seconds from queue admission. Socket admission is nonblocking with deadline-driven polling; queued connections carry their original admission deadline. A full listener backlog either refuses immediately or expires within that deadline. `Pending {stop_acknowledged, reason}` means termination is unconfirmed and retains Child, stdin and storage. A later call can inspect progress. An acknowledged stop is never followed by a signal, forced wait or premature stdin close. `Complete(Cleanup)` requires an actual successful reap; its fields separately report exit code, stop acknowledgment, daemon profile/socket absence and launch-storage removal. A nonzero exit or missing cleanup flag is never presented as a clean shutdown.

The launcher never signals any PID or process group and never removes the daemon profile. Only the daemon owns that cleanup. The launcher removes its own generated HOME/root only after confirmed reap and a fresh identity check. A replacement seen by that check is retained. Removal then uses path-based `remove_dir_all`: a malicious same-user swap between check and removal remains outside this cooperative boundary. Descriptor-relative recursive cleanup is not claimed. Cleanup results are cached once; a false removal flag remains visible and later shutdown calls do not retry deletion. Last-authority drop returns without waiting: if no stop was acknowledged, its lifecycle worker closes the exact child's stdin to request EOF shutdown, then retains ownership until reap. With an acknowledged stop it keeps stdin. Dropping a pending launch future similarly abandons only the result; the worker admits or rejects the child and runs the same teardown. Bounded caller return does not imply bounded child termination.

Any wait error except EINTR latches `Unknown`. That child is never probed, signalled or waited on again. Unknown state and descriptors are deliberately retained for the process lifetime, with no unproven cleanup. The parent process must keep children waitable: no SIGCHLD ignored, SA_NOCLDWAIT, or global wait-any reaper. Waiting for one's own child by handle is compatible. The library does not install signal handlers or a global child reaper. Receipt/identity failure closes stdin and follows the same signal-free retention policy; unknown or still-running cleanup is not silently claimed successful.

## Facade

All async methods use an internal standard-library I/O thread and executor-independent one-shot futures. A caller can use a GPUI executor, Tauri executor or `futures::executor::block_on`; no caller-thread Tokio runtime is required.

| API                                                        | Wire behavior                                                                                                                                                                                                                                                             |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Client::connect(endpoint, options)`                       | Returns `(Client, Hello { wire, capabilities, owner }, Notifications)` after `daemon:status`. Protocol 1, expected owner PID, `closing: false`, string capability/method lists and both paging capabilities are required. Status metadata is diagnostic, never authority. |
| `project_current()`                                        | `project:current([])`; preserves the Project body and checks the generated Project path.                                                                                                                                                                                  |
| `project_read(path, with_state)`                           | `project:read([path, {state: bool}])`.                                                                                                                                                                                                                                    |
| `state_read(scope)`                                        | `state:read([scope])`, returning actual `state`, `version` and `epoch`.                                                                                                                                                                                                   |
| `chat_runs()`                                              | Global `chat:runs([])`, returning `{runs, seq}`. Run sequence is distinct from global wire sequence.                                                                                                                                                                      |
| `chat_messages(scope, numeric_id, {before, turns, limit})` | `chat:messages([scope, numeric_id, options])`; absent options stay absent. IDs/options must be JSON-safe unsigned integers. Returns the actual raw body and metadata. No cursor fields are invented.                                                                      |
| `open_view(path)`                                          | Explicit `project:open([path])`. It may recover or persist owner state. It is not a mutation-free read.                                                                                                                                                                   |
| `runtime_snapshot()`                                       | Captures and assembles `daemon:snapshot([{paged:true}])` plus `daemon:snapshot-page`. Returns `RuntimeSnapshot {body, event_seq}` with a private receipt.                                                                                                                 |
| `accept_snapshot(&snapshot)`                               | Local acknowledgment only, after the caller applies the snapshot. No RPC.                                                                                                                                                                                                 |
| `disconnect()`                                             | Closes this connection. Never stops the fixture owner.                                                                                                                                                                                                                    |

Only the exact generated Project scope is admitted. There is no raw RPC or Chat/content mutation API. Omitted, malformed, unsupported and foreign inputs fail visibly. Unknown fields in successful raw bodies and remote errors are preserved through `serde_json::Value` for version 0.1. Lossless JavaScript lone-surrogate JSON requires a separate boundary decision; this serde-based client rejects such frames rather than substituting characters.

## Ordering, resync and failures

`Notifications` is one ordered consumer of `Notice::Event {wire_seq, scope: Option<String>, channel, payload}` and one terminal `Notice::Closed(error)`. Wire sequence must increase on a connection, but gaps are allowed. Events are held from handshake and whenever snapshot capture starts. Starting another snapshot also holds already queued, unread events.

`runtime_snapshot()` validates the manifest and body watermark. It does not release events. `accept_snapshot` requires the exact connection and latest capture generation, refuses foreign, altered-watermark and stale receipts, and prevents accepted watermarks from regressing. Accepting the same current receipt twice is a no-op. Equal watermarks across successive captures are valid when the daemon emitted no event. It discards held events at or below the accepted global watermark and releases later events in arrival order. Events arriving subsequently at or below the accepted watermark are also discarded. A higher run `seq` never affects this barrier. Concurrent captures serialize; a later capture invalidates every earlier receipt, including an earlier accepted one. Hold overflow produces one terminal Closed notice; it never silently drops events above the watermark while keeping the connection usable.

Result paging (`result-pages-v1`) is internal and accepts the wire's positive safe numeric or nonempty string page IDs. Snapshot paging (`snapshot-pages-v1`) is separate. Page count, aggregate bytes, JSON, page identity and snapshot watermark mismatches fail without a partial result. The whole operation, including queue wait and pages, shares one deadline. Once the original request returns a page manifest, even a later page timeout before its own write reports `submitted: true`. A timed-out submitted request may still have executed; its later response is ignored and nothing is retried.

Errors preserve `Remote {code, message, payload}`. Launcher failures retain a fixed `Launch {code, message}` classification. Local cases include `Disconnected`, `Busy`, `TimedOut {submitted}`, `Capability`, `Protocol`, `InvalidScope`, `StaleSnapshot` and `StateTooLarge {hydration}`. `Cancelled` is reserved for a future explicit local cancellation handle; dropping a future provides no result and only abandons its local wait. It does not free an admitted request early, cancel owner work, send a nonexistent cancel RPC, or trigger replay. Dropping an unpolled async call admits nothing.

Automatic deferred hydration of oversized Project events is not implemented in this checkpoint. A `stateTooLarge` event closes with `StateTooLarge` carrying its scope and required `project:read`; it never publishes a fabricated empty state. Reconnect and snapshot resync remain explicit. State patches, reduced Chat payload negotiation, computers, Links, remote endpoints and production authentication are not claimed. Existing Tauri transport has broader behavior and has not been replaced.

## Bounds and worker lifetime

Defaults are at most 32 accepted operations (queued plus active), 16 MiB per wire frame, 1,024 queued/held events and 16 MiB serialized event bytes, 1,024 pages and 128 MiB assembled result bytes, and a 30-second operation deadline. Options may only reduce these bounds. Admission credit releases before reply publication, including rejection; a caller awakened by completion can immediately use the returned slot. This first engine serializes wire operations; it is not yet the Tauri transport's concurrent RPC multiplexer. Notification bytes measure serialized payload size, not exact heap allocation or process RSS. One bounded terminal error slot is additional to the event queue. Overflow closes the connection; an already released prefix remains ordered, while events held behind an unaccepted snapshot are discarded.

The socket worker owns no writer or child. Dropping the last Client sets stop and shuts down its exact socket without blocking the caller on a join. The worker retains authority until its reads/writes finish and its loop exits. I/O uses bounded timeouts; OS scheduling and a blocked filesystem remain outside wall-clock guarantees. The launcher connector has a three-second response bound and a 32-control queue. The worker is not a replacement for the retained-child supervisor. A dropped connection attempt also drops the eventual Client result and closes that socket. No background request or reconnect loop survives through a public discovery service.

## Validation and remaining work

Run `cargo test --offline --locked`, `cargo clippy --offline --locked --all-targets -- -D warnings`, `cargo fmt --check` in this crate. The ordinary suite has 36 tests, three compile-fail doctests and one ignored real-daemon test. Ignored is not passing evidence. Synthetic tests cover exact requests, read shapes, result/snapshot pages, snapshot receipt identity, monotonic global barriers, dropped waits, bounded admission, publish-after-credit-release, operation-level paging timeout accounting, late replies, remote refusals, overflow, visible hydration refusal, fragmented frames, reconnect and local cleanup. Launcher tests cover acknowledged Pending, sticky Unknown, EINTR, no post-reap probe, path/socket/executable replacement, unsafe modes, exact peer PID mismatch, nonblocking/CLOEXEC setup, saturated-listener connect and shutdown deadlines, bounded receipt/deadline and explicit identity-checked storage cleanup. Compile-fail examples pin absent path/socket constructors and private snapshot receipts.

For the real macOS check, first have the runtime owner build `experiments/rust-runtime/target/debug/app-fixture` from the agreed source. Then run from the repository root:

```sh
python3 experiments/rust-daemon-client/scripts/check-owned-fixture.py
```

The script has no executable or profile override. It builds only this crate's test runner offline/locked, stages that runner beside the fixed runtime binary, records both SHA-256 hashes and the checkout HEAD (explicitly not a source-to-binary attestation), and runs exactly the ignored `launcher::tests::owned_fixture_end_to_end` test. The private staging directory is removed and a synthetic parent-HOME canary must remain unchanged. The fixture is never launched inside an installed app.

The real test covers all six reads plus explicit open, snapshot acknowledgment, socket-mode tamper refusal and restoration, reconnect to the same PID, and three private scripted sends that force result and snapshot paging beyond the runtime's 4,096-byte frame limit. Scripted writes exist only in `cfg(test)`; no public write grant is added. It checks transcript total six and the summary, then requires stop acknowledgment, exit 0 and absence of daemon profile, socket and private launch root. A second child survives Client drop, accepts another reader, and cleans up after last-authority drop. A third real child is paused after receipt/peer admission and before result publication; dropping the launch waiter and releasing the test-only barrier must clean up without signals. Evidence markers report these checks separately. This is fixture compatibility evidence, not production-provider execution or native UI evidence.

Remaining gates: automatic oversized-state hydration; measured concurrent multiplexing; shared adoption by Tauri and the off-by-default GPUI adapter. A live oversized event still closes visibly and requires explicit reconnect/resync. GPUI owns presentation DTO mapping and reducers, not endpoint authority. Scripted send/approval/interrupt needs a separate public write capability. Design/Artifact authoring follows the native content gate. None of those later stages is completed by this crate.
