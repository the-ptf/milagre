# Isolated Rust read, Artifact and terminal runtime

This crate connects `milagre-owner-wire` to `milagre-owner-store`, `milagre-terminals`, `milagre-content-store`, `milagre-ports` and the bounded `milagre-git-read` service. The unchanged production Node daemon client and desktop runtime client read real saved Project files through a Rust server. It is a tested integration boundary, not the installed app's backend or a completed owner migration.

The read/PTY/Git server executables accept **no arguments and no existing profile path**. Each run creates a private fresh profile under canonical `/tmp`, copies embedded repository fixtures into its hidden `.projects` directory, and binds a distinct Unix socket. It ignores `TMPDIR` when choosing the profile. None binds the production profile, starts providers or writes existing Project data. The separate `git-runtime` executable additionally creates and initializes its own disposable Git repository before binding, then exposes reads only. The default executable keeps copied Project bytes sealed. The `owned-runtime` executable takes writer locks and may compact sidecars only in its own fresh marked copies. Real PTY shells start only after an explicit `terminal:open` request. EOF on stdin or `daemon:stop` tears down its own temporary profile and socket.

```sh
cargo test --manifest-path experiments/rust-runtime/Cargo.toml
cargo clippy --manifest-path experiments/rust-runtime/Cargo.toml --all-targets -- -D warnings
```

`cargo run --manifest-path experiments/rust-runtime/Cargo.toml` starts the isolated executable, prints its temporary profile/socket metadata, and waits on stdin. `cargo run --manifest-path experiments/rust-runtime/Cargo.toml --bin owned-runtime` starts the separate ProjectStates-backed variant. Its 4 KiB frame limit intentionally forces the production client to page ordinary Project reads. Do not use this configuration for performance comparisons.

## Implemented read surface

| Method                                           | Current behavior                                                                                                                                                                |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `project:open`, `project:switch`, `project:read` | Read an embedded fixture copy, register it as opened, return path/name/git/state. No Git discovery, registry mutation or resume work.                                           |
| `project:current`                                | Return this connection's selected Project; the first embedded Project is the isolated launch default.                                                                           |
| `project:snapshot`                               | Read an opened Project's saved state with sidecar hydration and in-memory detail compaction.                                                                                    |
| `state:read`                                     | Whole state with a process-specific epoch and content revision. Sealed copies remain version 1; a later different whole state increments it. No state-patch support is implied. |
| `chat:messages`                                  | Production Chat paging. Unopened database-backed copies read raw rows; opened copies use compacted state. Legacy inline copies must first be opened.                            |
| `chat:message`                                   | Find a saved message and hydrate its tool-detail sidecar.                                                                                                                       |
| `chat:send-status`                               | Return a saved-message or queued-entry receipt, or null. No send is performed.                                                                                                  |
| `chat:inbox`                                     | Saved idle-Chat completion/failure projection, using the shared contract for titles, unread filtering, UTF-16 previews and ordering.                                            |

`ReadBackend` has two implementations. `SavedCopies` uses `ProjectReader` and `ProjectRepository`, rejects changed bytes, and proves reads leave its copies unchanged. `OwnedCopies` uses the actual `ProjectStates` manager, initializes `Isolation` before any fixture files exist, and takes owner locks only on those copies. It serves whole states through lazy storage without loading every Chat into the in-memory state. It also exposes `chat:all-messages` (including marks/withState), `chat:search` and `chat:subagent` through `ProjectStates::call`, and uses its bounded inbox previews. Calls advance the storage manager's clock; shutdown closes it and releases its locks. There is no automatic service timer or Project mutation command yet.

Paths must exactly match this run's copied fixture catalog. Both modes reject symlinks/hard links and external paths through their storage boundary; the sealed mode also verifies immutable bytes. No stored Worktree path is followed. This is experimental isolation, not protection against a hostile process running as the same OS user and racing filesystem operations.

Known unsupported mutation/service names return `UNSUPPORTED_MUTATION` with the message `The isolated Rust read runtime does not execute mutations or start services`. Unknown names return `COMMAND_FAILED` with `Unknown command: <method>`. Registered unsupported methods are intentional failures, not advertised functional services. Only result/snapshot paging capabilities are advertised; there is no `desktop-v1` or state-patch capability.

## Real terminal service

The eight production `terminal:list|profiles|setShell|open|read|input|resize|close` methods route through `milagre-terminals::wire::handle`, with a server-generated client identity. `terminal:changed` and `terminal:preferences-changed` events use the shared wire event stream. A viewer disconnect does not close its shell. Host shutdown disposes PTYs before deleting the profile; the fixture chooses process-tree cleanup for its own shell descendants.

The resolver admits only a non-archived Chat in the embedded catalog. It maps that Chat to the copied Project directory, rejects an arbitrary `cwd`, and never follows the original saved Worktree path. This is a fixture mapping, not completed production Worktree resolution. Shells are real `/bin/sh` processes, with a small explicit environment, no inherited credentials, no login startup files, and in-memory shell settings. Shell selection is restricted to `/bin/sh` in this fixture. A terminal still has normal OS filesystem access: these restrictions and tests are not a process sandbox.

## Owned Artifact and Design services

Only `owned-runtime` enables saved `artifact:list|get|asset|comments` requests. Recorded Node-generated HTML metadata, tabs, comments, assets, a saved Design and immutable Project kit snapshots are copied into the fresh profile before its content writer opens. Both the Artifact owner and the selected Project owner must verify their locks for each call. Chat identities must refer to a real Chat in an opened fixture Project. Corrupt storage, unsafe files, I/O errors or lost ownership permanently disable this Artifact service; restoring the file does not reactivate it. This matters because legacy Artifact reads can migrate saved files. Ordinary invalid requests and missing assets remain domain errors. The owned mode also exposes the production `artifact:apply` command for saved Design edits. It calls `prepare_design_apply`, reads authoritative immutable kit snapshots through native `DesignKits`, and commits a fresh preview with native `design::render_html`. Calls serialize through the Artifact service; concurrent edits with one expected version produce one new revision and a conflict. Saved Design reads support the production `fonts.have` cache contract. The full `summary/latest/html/document` reply drives the existing editor's local `DESIGN_SAVED` event. Production emits no separate backend Artifact change event, and this adapter does not invent one. Artifact/Design deletion, comment writes, HTML creation and export remain unsupported. `designs:enabled:read|save` retain production's always-enabled retired-switch behavior.

Kit read/save and Design show/read are agent tools in production, not daemon commands. The adapter uses kit reads internally and exposes no invented kit/show wire endpoints. Agent-facing Design image feedback and warnings still need their real tool-host integration.

## Terminal port discovery

The owned mode also enables `agent:ports`, `chat:ports`, `agent:ports` events and actual port snapshots. The watcher derives its roots only from this process's private terminal shells. It does not admit provider PIDs or external roots. The sealed mode has no watcher. `agent:stop-port` is enabled only for this owned-copy watcher. The reviewed library verifies the listener's kernel birth time and process group against its previous listing and a fresh poll, then rechecks identities before each signal. Terminal/root groups are protected. The adapter independently samples current shell descendants before each signal, rejects PID/PGID -1, 0 and 1, and rejects a group containing any unrelated process or the terminal shell itself. A wrong Chat, unrelated PID or malformed request returns `false`. These are isolated fixture descendants, never production roots.

## Isolated Git read integration

`cargo run --manifest-path experiments/rust-runtime/Cargo.toml --bin git-runtime` starts an owned-copy runtime with one additional service. Before the socket binds, `IsolatedGit::create` makes a separate private repository under canonical `/tmp`, commits a tiny synthetic baseline, and prepares text, binary, deletion and secret-file changes. Its metadata reports this run's `git.root`, `git.cwd` and the copied `alpha` Project to which the fixture attaches. The fixture never imports an existing repository, follows saved live Worktree paths, fetches or pushes. The original two executables still start no Git process.

The four existing renderer methods `git:changes`, `git:history`, `git:diff-files` and `git:diff-file` call the real Rust `IsolatedGitReader`. Its empty private process environment ignores the caller's HOME, XDG directories, Git configuration and credential variables; hooks are disabled. The connection must first select the attached copied Project, the Project owner must verify before/after the query, the IsolatedGit capability must validate its marker/checkout/common Git directory, and cwd must be one of the exact admitted roots. A disconnected viewer must open the copied Project again after reconnecting. Git errors preserve their typed process details. Requests with lone UTF-16 units in Git paths/refs fail explicitly rather than alias another path. This is a restricted fixture mapping, **not** production Worktree discovery or completed authorization.

No Git mutation is registered. The capability is retained only to verify/read and clean up its own repository on shutdown. No `worktree:create` wire response is invented from the lower-level library result. The eventual owner still needs Worktree/Chat/Link registry rules, leases, setup/copy semantics and durable state publication.

The sixth real Node-client suite compares ten query cases with production `createGitActions` and `createGitDiff`, verifies repository file hashes before/after, tests per-connection selection/reconnect, refuses external cwd/traversal/mutations, checks lost Project ownership, and passes with the runtime launched under a foreign HOME containing invalid Git configuration. Node's oracle uses analysis-only Git with a private environment. Only this test-owned repository is inspected; no installed profile or real Git data is used.

## Evidence and limits

Seven Node integration suites launch the separate Rust binaries and connect the actual `apps/daemon/src/client.cjs` and `runtime-client.cjs`. The sealed-reader suite compares results with actual Node `readProjectState`, `chatPage`, `withDetails` and shared `inboxSnapshot` on **separate disposable oracle copies**. Node's readers can write/compact sidecars or initialize SQLite, so they never read the server copies or source fixtures directly.

Coverage includes four copied Projects (`alpha`, `legacy`, `surrogates`, and a >100 KiB paging variant derived from the legacy fixture), database and inline messages, message details, queued/saved receipts, per-client Project selection, numeric page manifests, ordinary and snapshot pages, stored lone UTF-16 surrogates, inbox parity, external-path rejection, explicit mutation errors, byte-identical server files after reads, file-change refusal and symlink refusal. Real terminal coverage includes all eight commands, cwd/archived-Chat refusal, output and UTF-16 offsets, resize checked with `stty`, replay after disconnect, shell identity preserved across viewers, events, and shell cleanup on daemon shutdown. The tested shell commands do not change Project bytes. The wire suite separately proves UTF-16-aware ordinary replies, event payloads and snapshot serialization without reinterpreting page fragments.

The owned-runtime suite constructs actual Node `ProjectStates` on separate oracle copies, observes old Chats unloaded, and compares whole/lazy reads, marks, details, receipts, search, subagents, inbox and large snapshots. It verifies that the Rust process owns only its copied Projects and that refused send commands create no receipt or coordination-file change. Both reader suites pass with real Unix PTYs. This does not prove any provider execution or a live profile cutover.

The Artifact suite compares actual Node Artifact reads on a separate disposable oracle copy, including current-version redirects, tabs, comment state, chunked assets, argument errors and large paged replies. Four fresh runtimes prove permanent refusal after Artifact-owner replacement, Project-owner replacement, a nonregular asset file and corrupt saved metadata. The tests restore the fixture files without reading or logging owner tokens, and verify unchanged content bytes after reads. Fixture regeneration is explicit: `node experiments/rust-runtime/fixtures/artifacts.cjs --record`.

The Design suite sends actual production `artifact:apply` calls and compares returned source plus HTML against Node using the committed revision's timestamp. It compares saved metadata values, every source revision's bytes and every rendered preview's bytes. Coverage includes font-cache hits/misses, retained versions, stale/conflicting concurrent edits, authoritative pinned-kit mismatch, explicit adoption of the newer kit, paging, reconnect reads, Project state/revision stability and independent viewer selection. Separate fresh processes reject a corrupt kit store (invalid JSON or schema) and replaced Project owner before saving any source/preview pair, then remain inactive after restoration.

The port suite starts a real loopback listener from its private PTY, observes discovery/events, disconnects and reconnects the production Node runtime client, and checks that the snapshot still contains the listener. Wrong-Chat, unrelated/root PIDs and malformed stop requests return false. The real `agent:stop-port` command then ends only that test-owned listener; the test waits for removal and confirms that its shell survives with the same PID. Host shutdown is checked for child cleanup. A Rust unit test covers the additional signal-target graph guard, including mixed groups, shell protection and reserved PID values.

A separate scripted actor executable now exercises that boundary; see `OWNER-INTEGRATION.md`. It does not replace the read/PTY/Git executables or the installed owner. The read/PTY/Git runtime does not expose versioned Project mutations or provider runs. The scripted actor owns a periodic write-behind/sweep driver but does not expose real provider runs, active approvals/questions, Project registries, Links, accounts, mobile/peer transports, or shutdown ownership handoff. Inbox scopes containing saved background/advisor work return `UNSUPPORTED_LIVE_INBOX`, because this runtime cannot establish live activity. Empty runs snapshots in the read/PTY/Git executables describe those fixture processes, which start no provider runs; port snapshots reflect its admitted terminal watcher when enabled. It does not claim production background-work parity.

The wire adapter now parses incoming requests with the owner's lossless JSON decoder. String IDs, receipt/search text, argument keys and domain values preserve lone UTF-16 units without conflating literal U+10FFFE/PUA marker characters. IDs use JavaScript UTF-16 length limits and echo through a paired serializer on inline, paged and error replies. Serialized page fragments bypass the domain decoder. The wire pre-scans nesting to 128 levels before recursive parsing, and existing frame-byte budgets still apply. Actual production Node-client tests cover saved receipt/search parity, 128/129-unit ID boundaries, paging and malformed/deep/oversized frames.

Native terminal/port crates use ordinary Unicode. The runtime decodes literal markers once before calling them; terminal input converts lone units to U+FFFD exactly as Node's UTF-8 PTY write does. A lone unit in a native identity/path is explicitly refused as `UNSUPPORTED_UTF16_IDENTITY` rather than collapsed onto another valid identity. This limitation does not affect owner storage strings, which remain lossless. Arbitrary locale collation of tied inbox keys is also deferred; admitted fixture paths and numeric Chat identities are ASCII. The sealed mode rehashes files before reads, and several queries still construct whole state: this is correctness scaffolding, not a performance result.

Direct dependencies are the six Rust path crates, `serde_json` with ordered objects, `sha2`, `hex`, and `tokio` for terminal async reads/disposal; exact resolved versions are in `Cargo.lock`. Neither the desktop nor production Node runtime is changed by this crate.

## Scripted owner actor

`cargo run --manifest-path experiments/rust-runtime/Cargo.toml --bin actor-runtime` creates another fresh private profile and a synthetic Project with two Chats. No path arguments, provider executable, live account or existing profile can be supplied. Its metadata explicitly says `scriptedProvider: true`; the provider is a deterministic in-process test implementation named `kiro`, not the Kiro CLI. This binary has no terminals, Git or Artifact services.

One thread owns ChatHost and its ProjectStates. Commands enter a 64-request / 8 MiB bounded queue; a full queue refuses immediately. Monotonic 20 ms ticks coalesce in that same loop, pump the bounded scripted event schedule and advance saves/sweeps even without connected viewers. Fixture intervals are 100 ms debounce, 350 ms idle and 100 ms sweep; these are test settings, not production defaults or performance measurements. Every transition updates the cached snapshot and emits its notices under the wire publication lock. Snapshot handling reads that cache directly instead of asking the actor while holding the lock.

The seventh real Node client suite proves periodic save and idle unload without another RPC, a blocked synthetic start while another Chat completes, per-view scope checks, snapshot/reconnect/interrupt, publication sequence order, repeated concurrent snapshots, and a failed close that leaves the lock present and admission closed until a repeated stop succeeds. Four unit tests cover bounded admission, closed admission, scripted event capacity and retention of unsent events after a publication failure. All six earlier read/content/terminal/Git suites remain unchanged and pass.

This is not production shutdown or provider parity. The fixture explicitly interrupts its synthetic turns before close; production suspend/resume is still gated. The actor uses owner checkpoint `37264274` with mandatory turn/session generations and `ChatHost::tick`. Additional scripted cases deliberately drop interrupt completion, send idle duplicate ends and old-session exits, and emit events after `project:forget`. The 250 ms fixture watchdog forces the missing end; an old generation cannot fail its replacement or reopen a forgotten Project. Real provider process teardown and production suspend/resume remain unverified. Naming requests and sender-local queue notices are not serviced here, and steps/approvals retain the owner's gates. Transition errors are bounded and deduplicated on stderr; save failures also remain in the owner's persistence state. No live host, socket, Project, provider process or installed app is changed by this executable.

Event output uses a 256-entry pending FIFO. A failed publication retains its unsent entry and successors, closes ordinary admission and refuses snapshots with `OWNER_EVENT_FAILED`; a durable stop is still allowed. It does not silently resume a partially delivered stream. `state:read` receives its version after the cache commits. Timer pumping continues while admission is closed so delayed cancellation can settle; only a closed ProjectStates stops its save/sweep clock. Successful stop is the durability boundary. Forced object destruction after a failed stop logs a crash-equivalent teardown and may lose unsaved state; this experiment does not claim graceful-drop durability.

All four runtime executables now finish with `Server::finish`: after successful shutdown, they consume the remaining executable Arc handles and wait for the owned temporary profile destructor before `main` returns. This fixes a race where an EOF/stop worker outlived `main` and left its fixture folder behind. A deterministic wire test holds both kinds of reference until later, and eight consecutive actor integration runs verified cleanup. The read-only SQLite assertion waits up to one second for the fixture owner's brief commit lock; runtime cleanup promises are awaited so closed-server errors cannot become unhandled rejections.
