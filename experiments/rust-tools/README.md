# Native content MCP dispatcher

This isolated library runs the retained Design and Artifact tool definitions without Milagre's Node MCP server or Node SDK. It provides no listener or provider transport of its own and cannot open a live profile. The production host remains the sole live writer.

## API and owner contract

`ContentOwner::open(isolation, artifact_relative_path, kit_relative_path, project_for_chat, owner_active, runtime, raster)` opens the native `ArtifactStore` and `DesignKits` exactly once and returns `Arc<ContentOwner>`. `owner_active` verifies the authoritative content owner identity. `project_for_chat` must admit only real, opened Chats whose Projects the runtime owns, and return their canonical Project identity. The stores use these callbacks for their existing scope and write checks.

`owner.session(caller)` returns a lightweight `Dispatcher` over the same owner. `Caller` is an immutable owner-supplied Chat/Project identity, admitted Worktree roots, read/write permissions, separate HTML/Design/kit grants, Design-id scope, bundled skill directory and revocation callback. Its Project must match the authoritative resolver. No MCP argument replaces a grant. Every storage operation installs a scoped authorization lease on both stores, composing the base owner check with the current caller's revocation and Project-identity checks. All existing atomic-write checkpoints check that lease; Drop restores the base guard on success, failure or unwinding.

- `session.list()` returns implemented/granted schemas, descriptions and annotations.
- `session.call(name, arguments).await` returns MCP `{content, isError}`, including PNG blocks. `session.dispatch(frame).await` accepts one complete JSON-RPC frame and returns bytes or `None` for a valid notification. Both use `&self`, so independent sessions can share the owner.
- `owner.renderer(&caller, method, request)` implements the existing `artifact:list`, `artifact:get`, `artifact:asset`, `artifact:comments` and `artifact:apply` routes synchronously through those same stores. Renderer calls require the owner's full HTML/Design scope, the appropriate read/write capability, and an exact Chat match. They create no second writer.
- `owner.storage_fault()` reports latched unsafe-file, corruption, I/O and ownership failures. `owner.shutdown()` invalidates every retained session and drops both store handles under the lane before returning, even while session Arcs remain alive. It is idempotent; the runtime may then release its outer owner lock. Old sessions never attach to a replacement owner.

The full grant advertises 14 tools: `design_show`, `design_read`, `design_inspect`, `design_validate`, `design_apply`, `design_export`, `design_list`, `design_kit_read`, `design_kit_save`, `artifact_show`, `artifact_read`, `artifact_list`, `artifact_comments`, `artifact_resolve_comment`. `design_delete` remains excluded because the content store has not implemented it. Browser, voice, publishing and unrelated tools are absent.

One mutex serializes admission, reads, optimistic revisions and writes across Chats and both callers. PNG rendering starts only after the commit releases this lane. Another Chat or the renderer can read/edit while the first caller awaits its image; that image always uses the saved snapshot from its own revision. All calls recheck their grants before returning content. If revoked during PNG feedback, the caller receives an error with no saved content or image, while the committed version stays saved. Cancellation also leaves an already committed revision intact; adapters must not replay it. Shutdown closes storage immediately after the current synchronous operation; an in-flight PNG helper remains bounded by its existing timeout and cannot return content to a closed owner.

The convenience `Dispatcher::open` remains for single-Chat fixtures. Runtime code must use the shared `ContentOwner`, not open it alongside another ArtifactStore on the same directory. Session futures are `Send`; the synchronous schema/layout/storage phase should run on the owner's dedicated worker rather than block a shared async I/O executor. This crate provides storage serialization, not provider-run scheduling.

## Existing behavior preserved

`src/contract.json` is generated from actual `artifactToolDefinitions`, `htmlArtifactToolDefinitions`, `designKitToolDefinitions` and the local Designs group's `design_list`. Descriptions replace only the installation-dependent bundled-skill directory. The advertised schemas remain exactly Node's JSON Schema; a separate generated parsing snapshot records Zod's strict/strip/passthrough behavior. The Rust interpreter rejects unsupported schema keywords, enforces strict top-level arguments, handles record keys, discriminated alternatives, integer bounds and installed Zod's Unicode code-point string limits. Unknown fields in open layer inputs still reach the stricter native Design engine, as in production.

Show/apply commit fresh native HTML before computing feedback. Feedback preserves summary JSON on the first line, warning limits, intent-specific guidance, font/glyph limitations, remote-image notes and PNG blocks. A failed or unavailable preview adds the existing warning and does not undo an already saved version. Inspection includes bounds, crop, diagnostics and preview limitations. JSON/SVG exports, validation, pinned kits, tab selection and comments use the native store, with the existing version/conflict rules. PNG compression bytes may differ; decoded pixels match the Node WASM renderer in tests.

The helper binary is `milagre-design-raster`, built from the content-store helper entry point. Pass a trusted absolute executable path in one shared `RasterRenderer`; never accept a helper path from a tool argument. A `None` renderer deliberately exercises production's saved-version/failed-preview behavior, with an explicit unavailable-helper message. Packaging the helper and connecting tool images to the provider remain integration work.

Scoped Designs filter discovery, saved ids and comments. This implementation also checks `from.id` when copying a variant; current Node checks only the target id, so Rust deliberately prevents copying an out-of-scope source. Worktree roots must resolve to directories inside the Isolation. Their canonical location is rechecked with the caller's guard, so replacing a root with an outside symlink stops later requests. This is not protection from arbitrary external filesystem changes between individual syscalls.

## Protocol and limits

The dispatcher implements `initialize`, `ping`, `tools/list` and `tools/call`, with production protocol versions `2025-03-26` and `2025-06-18` and serverInfo `{name:"milagre",version:"1"}`. Unsupported requested versions negotiate to `2025-06-18`. Unknown tools return the existing tool-error content; unknown methods return `-32601`. No resources or prompt capability is advertised.

Frames are limited to 1 MiB, except Design show/apply at 6,000,000 + 64 KiB. Replies are capped at 32 MiB. Input parsing retains lone UTF-16 surrogates through the existing `jsjson` representation. Nested schema interpretation stops at depth 80; JSON parsing has its existing recursion limit. Calls share the ContentOwner storage lane; the native raster helper separately bounds its queue and process lifetime.

There is no HTTP, stdio, bearer-token, grant registry or Claude/Codex transport adapter. Thus malformed frames produce ordinary JSON-RPC parse/invalid-request errors instead of the Node HTTP server's empty 400 response; oversize requests produce `-32000` without an HTTP status. The future transport must enforce authentication, framing, connection revision, HTTP headers or provider-specific routing before calling this library. It must not replay a call after cancellation: a write may already have committed before PNG feedback finishes.

## Independent host role guard

`owner.session(caller)` preserves ordinary grants. `owner.session_with_policy(caller, policy::PolicyOptions)` admits an immutable `HostRole` and optional manifest subset. The native handler registry classifies each implemented operation's effect; admission checks generated Node annotations against that registry. An owner-supplied manifest can only narrow registered/granted tools and must match each effect exactly. Unknown names, duplicate names, unsupported handlers and relabeled writes fail admission. The resulting private manifest drives both `tools/list` annotations and `session.provider_manifest()`; adapters must use that snapshot rather than independently assembling tool metadata. Changing the returned snapshot cannot mutate the session.

Every direct `call` and JSON-RPC `tools/call` enforces that manifest before argument validation or execution, even when no provider adapter is involved. Provider `Full`, `readOnlyHint`, permission metadata and caller write permission cannot override the role. Role and wake scope have no mutation API. `AnalysisAdvisor` exposes only the nine read operations. `Babysit` and `ExecutionAdvisor` are unsupported and fail before a session is created.

`HostRole::Escalation { wake_id, requests }` requires a nonempty immutable wake id, valid distinct Chat/request pairs and a trusted nonblocking `on_sealed` callback. It currently exposes read tools only: this content host has no `chat_respond` handler, so even an authorized pair cannot execute that tool. Wrong Chat/request pairs are checked and denied independently; future response support requires a real scoped handler and registry entry. Explicitly requesting any unsupported or write capability for a constrained session fails admission instead of silently replacing it with Ordinary.

Escalation atomically reserves one slot for every attempted host tool call, including unavailable tools, bad arguments and repeated JSON-RPC ids. Exactly six calls can reach execution. Attempts seven and eight return Node's reply-now message; the ninth seals the budget and invokes the owner's stop callback exactly once. The counter saturates at nine, and a callback panic cannot unwind the dispatcher or reopen the budget. `session.budget_status()` reports attempts and sealed state. A sealed callback must reliably signal the provider turn; the host itself starts no provider and cannot confirm that the provider stopped.

A wake id can be admitted only once per ContentOwner, including after its session is dropped, so creating another endpoint cannot reset its budget or change its request pairs. At most 256 wakes are admitted during one experimental owner's lifetime; further admission fails explicitly. Clone an `Arc<Dispatcher>` to share an existing wake across transports. Only trusted owner code may create a fresh wake id for a new wake. Host calls are counted independently of provider-native tool events: the provider must continue enforcing its own full-turn budget and sandbox policy. This checkpoint does not validate constrained CLI startup or add provider transport wiring.

Seven direct-host tests cover matching discovery/provider metadata, misannotated and missing manifest entries, writes with Full/read-only metadata, unsupported roles, wrong wake targets, 32 parallel calls producing exactly six successes, one stop after two grace denials, denied-call counting, callback panic, wake-reuse refusal and the admission cap. An additional runtime-generated fixture compares twelve calls with the real Node `EscalationTurn` budget and stop behavior, without a provider approval adapter.

## Verification and gaps

```sh
cargo test --manifest-path experiments/rust-tools/Cargo.toml
cargo clippy --manifest-path experiments/rust-tools/Cargo.toml --all-targets -- -D warnings
node_modules/.bin/oxlint experiments/rust-tools/fixtures/*.cjs
```

Twenty tests currently pass. The conformance fixture executes 63 calls through Node's actual command dispatcher and actual content/kit stores in a temporary Isolation. It compares tool success/error shapes, text lines, parsed JSON values and decoded PNG pixels, including create/edit/variant/inspect/export/validate, kit conflicts, HTML tabs, comment resolution, field errors and supplementary Unicode. One comment snapshot is seeded from Node's real `addComments` output to represent a user-authored comment. Generated schemas, descriptions, annotations and source hashes are checked against current Node every run. No network server, provider turn or production data is involved.

Boundary tests cover protocol negotiation, notifications, unknown tools/methods, malformed and oversized frames, UTF-16 request ids, unsupported-tool discovery, read-only grants, allowed/forbidden Design ids and comments, cross-Chat argument rejection, variant-source containment, grant revocation, swapped Worktree roots, corrupt-storage latching and `Send` compatibility for an owner actor.

Shared-owner tests add two concurrent Chats, concurrent renderer/MCP expected-version conflicts, shared Project kits, cross-Project/Chat/grant denial, independent revocation, owner-identity loss, reads during pending PNG, revocation during PNG without undoing a commit, shutdown with retained sessions and reopening the released stores. Separate mid-commit tests revoke a grant after Design HTML staging and before a kit rename: the staged write rolls back, the original version stays readable, and another grant can still write. This verifies both scoped guards are restored rather than leaking the revoked grant into the shared owner.

Remaining limits: the 63-call fixture is not exhaustive; native Design-engine structural error wording can still differ from Zod's complete diagnostic envelope (the content-store README documents this). HTTP and SDK-adapter interoperability, provider-run scheduling, desktop/mobile events and installed WebKit behavior are not verified by these tests. No user-facing service is advertised as migrated because this library passes.
