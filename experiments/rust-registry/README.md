# Isolated Project registry and Link scope foundation

Rust registry reader and separate single-writer service for synthetic or copied files inside an existing `milagre_owner_store::Isolation`. Reads admit only saved, freshly verified Project identities. Writes require a fresh copied-store capability. Neither service creates Projects, Chats homes or Worktrees. Node remains the sole production owner. This crate is not wired into the runtime or installed app.

## Runtime-facing API

- `Registry::open(isolation, profile_relative_path, active)` requires an existing non-symlink directory inside the marked isolation. It pins Unix device/inode identities of both the isolation root and profile. `active` is an owner-provided, thread-safe nonblocking snapshot check; it must not perform actor RPC. No default profile discovery exists. The owner must revoke `active` on shutdown; dropping one Registry handle does not revoke its clones or grants.
- `registry.snapshot()` implements `createProjectRegistry(...).snapshot()` filtering and preserves saved ordering/unknown fields. Missing/corrupt JSON produces the same empty snapshot as Node. `recent()` implements the recent menu's normalization, first-duplicate retention, existing-folder filtering and ten-item cap. Neither is authorization by itself.
- `registry.identify(path).await` returns Node-shaped `{id,path,name,git}` identity and active Worktrees. Git Projects use the canonical common Git directory and main checkout; linked Worktrees and subfolders resolve to that same identity. Plain folders use their real path. Folder-only Chats homes honor `.milagre-folder-chats` and enumerate valid `.chat-folders/chat-...` directories. Identity discovery alone admits nothing.
- `snapshot.project(path).await` mints an opaque `ProjectGrant` only when the discovered identity's id and canonical main path match a saved registry entry. `contains_folder(path).await` rechecks identity and admits only exact active roots, never arbitrary descendants. A real path alias of an admitted root works. A plain subfolder is its own identity and needs its own registry entry.
- `snapshot.link(id).await` mints a `LinkGrant` only for a saved valid named ProjectGroup with every member freshly resolved. `link.check().await` checks the saved generation and each current member. `snapshot.reachable(&project_grant, worktree).await` resolves one-hop canvas Links using fresh registered identities and active Worktrees, returns `LinkedGrant`s carrying the reaching Link IDs, and never uses arbitrary caller-supplied paths as grants. `LinkedGrant` exposes target identity metadata and one exact Worktree, never a `ProjectGrant`. It cannot be passed to `reachable` for a second hop or used to authorize another target Worktree. `LinkedGrant::check().await` recomputes the original source Worktree, each reaching Link id and exact target using fresh Git state. The registry fingerprint alone does not cover Git state. Any registry byte change or owner revocation invalidates retained grants; callers reacquire rather than silently widening a stale scope.

`Registry::probe(path)` distinguishes `Ok(Some(identity))` (present), `Ok(None)` (definitely missing) and `Err` (unverifiable). Only a missing/non-directory component under the isolated root without a preceding symlink or I/O error proves absence. Probe capacity, timeout, metadata limits, unsupported configuration and permission errors propagate. Reader Link discovery and every writer cleanup refuse unverifiable state instead of dropping it. Snapshots share their parsed registry through `Arc<Value>`.

Metadata accessors return previously observed records, not permanent authorization. Use the checks immediately before the runtime's operation and retain the runtime's own transactional owner checks; this library cannot make a later filesystem operation atomic with discovery. No `ProjectGrant` is constructed from a raw string, arbitrary JSON or a caller-provided active map.

`links` contains pure Node ports of group validity, endpoint compatibility, prune previews, named-Link member lookup and one-hop reachability. `scopes` ports shared Project/Link/computer/Chat key parsing. These functions intentionally accept evidence values and return metadata. They do not mint filesystem capabilities. Remote-computer scope strings can be parsed, but this local reader never executes a remote request.

## Isolated writer API

The exact production ordering and deliberate refusals are documented in [WRITE-CONTRACT.md](WRITE-CONTRACT.md).

- `writer::RegistryCopy::create(isolation, Seeds { registry, recent })` creates one new private directory, seeds it from bounded supplied bytes and returns an opaque copy capability. It never adopts an existing profile. `copy.reader(active)` returns a generation-aware reader for that same store; successful mutations invalidate old grants through changed registry bytes.
- `copy.writer(active, now)` acquires both pinned-directory and lock-file `flock`s. A second thread or process cannot become a writer. Every acquisition/write checks copy marker, pinned root/directory/lock identities, lock token and the nonblocking owner callback. `Writer` is exclusively borrowed across each `call().await`; drop releases OS locks without deleting a lock path. A retained copy capability can reacquire after clean close or a worker process exit. If all copy capabilities are lost, this checkpoint provides no adoption/recovery entry point.
- `writer.call(method, args).await` supports `register` (native verified identity from `{path}`), `position`, `worktree-position`, `group:create/update/delete`, `link:add/restore/remove/prune` and `recent:add/forget`. The fixtures demonstrate exact argument shapes. General registry mutations persist Node's stale-entry cleanup only if the requested mutation succeeds and every retained Project can be inspected. Unverifiable identity aborts without persisting any cleanup. Discovery has a 30-second operation deadline; the final synchronous commit does not yield. There is no Project-delete method in Node and none here. Native identity, active Worktrees and Link evidence are computed inside the copy, never accepted as renderer authorization.
- Writes use descriptor-relative `openat`/`renameat`, private 0600 staging, file sync, atomic replacement and directory sync. `WriteError.committed == false` means this call did not rename the target. `committed == true` means the rename happened but durability is uncertain: read current state and never replay automatically. Registry and recent files are separate transactions. Crash staging files are ignored and left untouched; they are never committed or adopted on restart.
- Blocking write work must run on a dedicated owner worker, not a shared async executor. Identity probes use bounded blocking workers; the final write has no await, so cancelling a discovery future cannot leave a later mutation running. The owner callback must be a nonblocking snapshot check. No production actor, wire routing, launch/switch policy or automatic retry is supplied. `Fault` and `writer_with_ids` are trusted test hooks, not renderer inputs.

The writer keeps Node's retained unknown row/group fields and drops unknown top-level fields exactly as Node does. Deliberate restrictions remain: Worktree positions and recent additions require exact verified roots; malformed saved non-object Worktree position maps fail instead of emulating JavaScript array-property behavior; files and output remain bounded. A same-user process deliberately replacing files concurrently is not made transactional with Git discovery, but pinned descriptors prevent following a replaced profile or target into outside files.

## Bounds and containment

Native capability access currently targets Unix file identities and `/usr/bin/git`; tested on macOS arm64. Scope-key parsing includes the production Windows path syntax, but native Windows identity discovery is not ported.

Registry JSON files are at most 4 MiB and 4,096 saved Projects/Links; recent input has the same entry bound. Files must be regular, singly linked, opened with `O_NOFOLLOW`, and unchanged during the read. Profiles and isolation roots cannot be replaced or aliased after opening. An input path is canonicalized and refused outside the isolation before its contents are read. Project/grant identity is checked against the saved registry, not just containment.

Git identity probes use fixed read-only commands, a cleared environment, no global/system config, `GIT_OPTIONAL_LOCKS=0`, no hooks/fsmonitor, a discovery ceiling at the isolation, a 3-second timeout per command and 1 MiB per output pipe. Git directories and `commondir` pointers must remain inside the isolation. Git is a subprocess; platform shim cache writes outside the copy are not audited by the fixture snapshot. Metadata traversal is capped at 4,096 entries before collecting directory children and refuses symlinks, hard links, config includes and `core.worktree` redirection. Chats-home listing is bounded before collection too. Git's absolute Git directory, top-level folder and common directory must equal the inspected metadata. Every listed Worktree must have a matching `.git` file and common-directory back pointer. Implicit bare repositories are refused before Git is launched. Worktree paths are canonicalized, including saved edge aliases; non-UTF-8 paths are refused. These restrictions deliberately reject large or complex copied repositories instead of treating unreadable Git as a plain folder. Up to eight probes per Registry can run; synchronous filesystem work stays on blocking workers. `snapshot()` and `recent()` are synchronous and should run on the owner's blocking worker. Cancelling a probe does not write or replay anything; its bounded read worker finishes and releases its permit.

Canvas capability discovery inspects at most 64 relevant Projects. Missing targets are excluded; a missing member of a named Link is an error. Malformed saved edges never create a capability. Replacing filesystem objects between checks is outside this snapshot foundation's guarantees; a production owner still needs guarded file operations and authoritative opened-state/Chat ownership.

## Node conformance and failure tests

`fixtures/node.cjs` invokes the real production modules on freshly generated folders, a Git repository and linked Worktree, a folder-only Chats home, symlink aliases and saved JSON variants. It writes setup files only inside the test's new Isolation. Tests compare **332 actual Node results** for registry/recent reads, identity/Worktrees, named membership, capability reachability, endpoint rules, pruning, one-hop Link aggregation, Unicode group validity and shared scope/computer keys. A recursive before/after snapshot verifies every fixture file byte, directory and symlink target stays unchanged during Rust reads.

Eight boundary tests cover wrong saved identities, nonregistered folders, exact-root versus descendant scope, unavailable Link members, revocation and registry generation changes, retained Linked grants after edge removal, registry file symlinks/hard links, escaping Git-directory pointers, copied-file size bounds and profile directory replacement. The read suite has nine tests. Nine writer tests add **42 real Node writer steps**, comparing operation result/error, exact bytes for both files, file-replacement versus no-op, clock/UUID call order and clean restart. They cover duplicate saved group ids, invalid memberships, unknown fields, recent-list cap, failed prerequisite cleanup, wrong roots, private modes, symlink/hard-link targets, directory/lock replacement, missing locks and the output entry cap. Cross-process flock exclusion, owner loss after staging, injected failures before staging/before rename/after rename and an actual SIGKILL-before-rename test exercise restart and uncertain-commit behavior. An additional unit test exhausts the probe slots and verifies that a mutation preserves saved bytes; a compile-fail test proves `LinkedGrant` cannot be used for a second hop. New regressions cover forged/missing Worktree back pointers, implicit bare repositories, redirected Git config, retained scope after source removal, alias normalization, missing Link ids, 4,097 metadata entries and unchanged files after unavailable probes. All 20 tests pass; clippy with warnings denied, rustfmt, oxlint and oxfmt pass.

## Inventory and remaining migration work

The existing Node services have distinct responsibilities that must stay separate:

| Production source                          | This checkpoint                                                                                     | Still Node / not implemented                                                                                                                                            |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `project-registry.cjs`                     | Saved `snapshot` filtering, generation-bound lookup and isolated register/positions/atomic mutation | `list` first scan, production write queue/owner integration and restart adoption after all copy capabilities are lost                                                   |
| `project-identity.cjs`, `git/client.cjs`   | Native plain/Git/folder-home identity and active Worktree discovery                                 | Missing-Git fallback nuances, old Git without `worktree list -z`, Windows paths, bare repos, large metadata and include-config repositories                             |
| `recent-projects.cjs`                      | Saved menu list and isolated add/forget                                                             | remember/open/launch/switch policy and production save failure handling                                                                                                 |
| `chats-home.cjs`, `chats-home-folders.cjs` | Existing folder-home identity and Worktree listing                                                  | Home `ensure`, Git init/empty commit, folder creation, launch fallback and ownership                                                                                    |
| `project-links.cjs`, `project-groups.cjs`  | Saved validation, one-hop reads and isolated group/canvas mutations                                 | Runtime shared-Chat/Worktree settlement, production undo and event publication                                                                                          |
| `linked-worktrees.cjs`                     | Registered one-hop scope foundation                                                                 | Chat-owned bindings, grants to extra Projects, shared-Chat restrictions, transcript reads, delegation/negotiation, hosted/remote targets, cached active-state lifecycle |
| `link-workspaces.cjs`                      | Existing named-member availability semantics                                                        | Preparation/session store, reservation, branch policy, setup review, alias manifests, restart recovery, release/removal and ownership                                   |
| `runtime.cjs:knownFolder`                  | Exact registered-root capability primitives                                                         | Full rule combining opened scopes, Chat Worktrees, Link workspaces and recent entries. The registry alone does not reproduce that runtime authorization rule.           |

`Registry::snapshot` intentionally does not emulate Node's mutating `list()`. The separate writer handles fresh isolated copies only; production lifecycle integration and authoritative opened-Chat ownership remain unported. This checkpoint does not claim Project/Link migration completion, live profile compatibility or installed WebKit coverage. JSON/I/O/Git failure text and strict containment refusals can differ from Node outside the tested successful read contracts.
