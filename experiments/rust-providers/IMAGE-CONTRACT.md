# Codex image boundary

Implemented in this crate only. No owner adapter is wired, no real provider turns were used,
and no production classifier or MCP dispatcher is assumed available.

## Owner API

`images::ToolImageStore::save(&self, mime: &str, base64: &str) -> Result<PathBuf, String>`
is signature-compatible with Claude's interface. The traits live in separate crates; an owner
wrapper can implement both without changing either provider. Set
`SessionOptions.image_store = Some(ImageStore(Arc::new(store)))` to enable output persistence.
The default is `None`, so there is no implicit output directory or filesystem write.

`FileImageStore::new(directory)` supplies SHA-256 filenames, atomic no-clobber publication and
0600 files on Unix. New directories are 0700; pre-existing directories and all ancestors must
be controlled by the owner. Final directory symlinks and destination symlinks, non-files,
public existing files or conflicting contents are refused. This does not secure a hostile
ancestor tree against replacement. Windows relies on the owner's private directory ACLs.

For inputs, validate with `ImageAttachment::from_base64` or `from_data_url`, then call
`prepare_input_images(prompt, attachments, private_scratch_directory).await`. The synchronous
`PreparedImages::create` is also available. Attach the result with
`turn(...).with_images(prepared)`. That sets the ordered input and retains temporary files.
`prompt_input(prompt, paths)` and raw input blocks remain available for host-owned paths, whose
lifetime is entirely the caller's responsibility. Scratch paths must be absolute so Codex's
child cwd cannot reinterpret them; caller-held `PreparedImages` or `TurnSettings` clones extend
file lifetime intentionally.

## Lifetimes and bounds

Each attachment accepts canonical base64, supported MIME and PNG/JPEG/GIF/WebP signatures,
up to 50 MiB decoded. Signature validation does not prove pixel decoding will succeed. Inputs
and outputs each have a separate per-turn limit of 32 images and 128 MiB. Steered inputs count
against the same turn limit. Output attempts reserve a conservative decoded-size estimate,
including failed saves, so malformed/repeated results cannot bypass the budget. The RPC frame
limit still applies independently and may reject a large image before this layer sees it.

Prepared inputs use a private temporary directory and remain alive through the whole turn,
including steering and rejected-steer fallback into a new turn. Completion, interruption,
crash, start failure, cancellation, close and last-reference drop release session ownership.
The owner must drop its clones to permit deletion. Preparation runs on the blocking pool;
cancelling preparation discards its result and cleans its directory once the task finishes.

Output persistence runs off the async executor, with one worker batch per session and a default
2-second wait (`image_save_timeout`). A timeout skips that batch's image events and leaves its
worker permit held until the callback returns. Later images are skipped while it remains busy.
The callback retains no session/process reference, and all text and terminal events continue.
A synchronous callback cannot be forcibly stopped, so the owner must keep it finite; a hung
callback can hold a blocking thread or delay runtime shutdown. The owner also owns output
retention, including orphan files from a save that finishes after timeout/cancellation.

## Event behavior and deliberate Node differences

Prompt ordering matches Node `promptImageBlocks`, including code masking, repeated references
and appending unused attachments. Only mapper-accepted current-turn completions are eligible
for persistence. A saved generated PNG adds `file` to its existing completion. MCP/dynamic-tool
image blocks produce the Node `step-started`/`step-completed` image pair with the original
content index. Internal Milagre `design_show`, `design_apply` and `html_preview` renders are
suppressed, including nested execution with preserved MCP provenance. Unsupported images or
store failures leave the tool's text result intact. Existing provider `savedPath` values pass
through without being read or copied; the owner must authorize any path before serving it.

Unlike Node's generated-image writer, generated bytes require canonical base64 and a PNG
signature, failed results are skipped, and filenames are content hashes rather than item IDs.
Foreign/stale generated completions cause no storage write. All output passes validation before
a custom host store is called. Saved paths must be UTF-8. The store must return a durable,
authorized local path and must never fetch arbitrary URLs.

Mapped agent events contain file paths rather than base64. Optional raw notification forwarding
still contains provider payloads, including base64; it is diagnostic data and must not be saved
as the user transcript. Generated output without a store (or after store failure) can retain a
completed image row with no file, matching the existing mapper contract. The owner should show
an unavailable-media state rather than infer a displayable image.

## Evidence

`node scripts/record-image-fixtures.cjs` executes the checkout's real Node helpers with temporary
storage and normalizes only output paths: 522 prompt traces, 26 tool-output traces and 13 payload
validation cases. Rust replays all 561. Existing 579 event traces and 189 policy fixtures remain
unchanged. Storage and fake-server tests exercise privacy, deduplication, corruption/symlink
refusal, budgets, output filtering/failure/timeout and input terminal paths. No live turns.
