# Retained persistent worker ownership

The first runtime checkpoint adds `persistent_supervisor::PersistentSupervisor` over a fresh `SyntheticProfile`, existing `supervisor::Limits`, and injected `Clock`. It owns one joined Rust thread. It has no command or approval client yet; those are the next separate checkpoint. No existing-store constructor, network, real HTTP executor, host process replacement or mobile changes are added.

`start` validates static limits and reserves the known control budget from the profile's existing global pool before writer acquisition. Resume outcomes retain their exact typed guard. After Running, failed startup reservation, spawn refusal or startup panic returns a dirty stopped owner. A capacity-one startup handoff precedes exposing the service. The startup owner holds its profile, retained runtime slot and any JoinHandle before waiting.

The worker borrows the authority from the retained slot. It never consumes terminal close. Its run-loop unwind is caught while ownership remains outside; outer unwind or poisoned slot recovery can only abort. Queue poison also stops admission. The out-of-band stop latch uses monotonic Running/Requested/Abort states and a separate sticky fatal fault. Abort dominates a healthy request. The worker's periodic tick currently services only its empty authority/registry; no carrier admission exists in this checkpoint.

`close_for_restart(self)` and `retire_identity(self)` stop and join before extracting the authority and calling terminal persistence. Successful receipts own the same profile and are decomposed through `into_parts()`. `abort(self)` and default Drop stop, join and revoke without terminal writes. There is no force path, join timeout or detached JoinHandle. Synchronous filesystem calls can delay shutdown. Unexpected unwind inside consuming terminal persistence remains outside the retained-result guarantee, as agreed; no clean retry or recovery claim is added.

`PersistentStartFailure`, `PersistentCloseFailure` and `PersistentReleaseFailure` each expose a redacted fault plus owning `StoppedService`. The stopped service retains the profile and any original writer guard. Releasing a read-only rejected authority restores only its previous eligibility after descriptor checks; failure retains Quarantine and the same profile. Dirty guard release never restores Clean. Explicit destruction remains the returned profile's existing borrowed `destroy` operation. `ServiceDiagnostics` reports optional validated store metadata and whether a thread was joined. No path, token, panic payload or arbitrary IO message is returned. The existing Rust panic hook can still print a panic when a test deliberately injects one; the service discards its payload.

Seven new tests cover joined quiescence before acknowledgment, clean replacement, static-limit correction, post-Running reservation refusal, spawn refusal, startup panic, poisoned retained-slot recovery, Abort precedence, every terminal IO stage, terminal retirement, explicit abort and default Drop. Drop is observed through a test-only alias of the same newly created capability: both locks release after join, the Running snapshot stays byte-identical, and reacquisition reports dirty. No public profile clone or import was added.

Approval permits, bounded commands/events, automatic carrier/approval deadlines, command panic/unknown outcome, stop under saturated queues and mailbox lease drainage are not claimed by this first checkpoint. The next service checkpoint must compose them before claiming persistent supervision of phones. Existing P3 fairness, duplicate DrainWork versus reserved revocation, Disconnect saturation and atomic real HTTP Claim remain separate. Production recovery/import, live pairing, relay/listeners and actual phone interoperability remain absent.
