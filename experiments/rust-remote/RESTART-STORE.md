# Fresh synthetic descriptor store checkpoint

`synthetic_store::SyntheticProfile` creates a new private marked directory under the OS temporary directory, generates synthetic box material and token bytes internally, and retains pinned root/marker/lock identities. It accepts no existing path, profile, keys, credentials or descriptor. It is a macOS-only prototype: other Unix targets return Unsupported; no Windows API is exposed. This checkpoint implements the descriptor store, not persistent authority or supervisor integration.

## Ownership and storage

- `create(StoreLimits, rng)` returns the fresh capability. `acquire_writer(&mut self)` returns a non-Clone, non-Sync WriterLease. An active writer or in-progress destruction excludes acquisition. Diagnostics return only the public profile id, validated revision/boot/retired state, and a closed redacted fault enum. `release(self)` and Drop write no snapshot and never acknowledge Clean.
- The worker independently opens and exclusively locks the pinned directory inode, then independently opens and locks the pinned writer.lock inode. Root, marker and lock identity/owner/mode checks precede snapshot reads or cleanup. Acquiring PID is checked before any inherited Rust lock or IO. No explicit flock unlock is issued; a dropped inherited alias must not unlock the parent. Root locking is proved on the current Mac; unsupported filesystems fail creation rather than falling back to path checks.
- The current capability owns marker.json, writer.lock and authority.json, with a single create-new transaction file during writes. Files are 0600 and the directory 0700. Writes encode a bounded snapshot, write, file-sync, descriptor-relative rename, then directory-sync. An internal non-Clone commit receipt binds profile, attempt and revision. Only a matching successful terminal receipt can restore the broker Clean acknowledgment. Any commit error poisons the lease, forbids another commit/acknowledgment, and retains both locks until explicit release/Drop.
- `destroy(&mut self)` excludes writers, validates all names before deletion, and unlinks only owned names. Transaction cleanup requires the exact inode tracked when this capability created it. Unknown entries or substituted paths are refused. Partial destruction retains the root lock and tracks deleted names; explicit retry handles only remaining owned names. Drop does not delete a persistent profile. Creation has a best-effort rollback guard for matching newly created inodes; an IO failure that also prevents cleanup may leave a fresh synthetic artifact, never a live writer.

The public WriterLease exposes read-only diagnostics/release. Snapshot reads, writes and Clean acknowledgment remain crate-private for the next authority checkpoint. A public caller cannot supply a snapshot or claim persistence success. A compile-fail test prevents sharing a writer across threads for concurrent snapshot allocation.

## Boundaries and crash evidence

The private v1 codec has fixed-size decoded keys, enums and checked integer fields, sorted unique device records, strict field/duplicate validation, and no arbitrary Value tree. It rejects escaped/large strings and excessive depth before deserialization. Limits cap input/output at 2 MiB, history at 4,096 slots, charged parsed state at 3 MiB and aggregate store working space at 12 MiB. Lower limits are enforced. Serializer output is bounded while written. Container capacity is reserved once within the configured record bound. A separate allocator-instrumented binary measures the actual codec, including 4,096 records and hostile compact/oversized inputs. The library retains `forbid(unsafe_code)`; allocator instrumentation is test-only.

The live capability's broker ledger consumes the previous Clean acknowledgment on acquisition. Dropping any unacknowledged writer leaves that ledger uncertain even if a Clean file is visible. Internal acknowledgment occurs only after successful syncs and writer release. This is retained-broker recovery, not recovery after losing that capability or rebooting the machine. It does not defend against a malicious same-UID process or privileged disk rollback.

Subprocess tests pass only the already-created synthetic root through inherited stdin and public expected identity metadata. There is no public FD import, worker launcher or arbitrary executable API. The private test worker opens independent descriptions. Tests prove:

1. Competing processes cannot acquire the root while a writer lives; replacing writer.lock does not bypass exclusion and is rejected after release. A child presented with an inherited locked descriptor refuses wrong-PID ownership; dropping its aliases leaves the parent's lock intact. Killing the holder releases its independently owned locks.
2. Two successive clean subprocess writers preserve the snapshot and matching broker acknowledgments. Running exit, absent acknowledgment and a failure after a visible Clean rename all make the next acquisition's diagnostics report DirtyRun. The test broker accepts only the expected attempt/revision/boot receipt from its own completed child.
3. Write, file-sync, rename and directory-sync failures retain exclusivity and never issue a Clean receipt; subsequent writes on that lease are refused. Wrong terminal receipt, checked revision overflow, root spelling substitution, replaced file, unexpected cleanup entry and partial-delete retry are tested.

The subprocess bootstrap/ack transport exists only in the test harness. The production library currently exposes only same-process retained-capability operations. Worker/broker-loss recovery, public subprocess supervision, persistent policy authorization, real keys and production profiles remain absent. Cleanup deliberately refuses an untracked transaction inode left by an external process rather than guessing ownership or recursively deleting it.

## Primary-source verification

Pinned dependency: rustix 1.1.6 (`fs`, `process`), with Cargo.lock checksums. The official API documents [descriptor-relative openat](https://docs.rs/rustix/1.1.6/rustix/fs/fn.openat.html) and [flock operations](https://docs.rs/rustix/1.1.6/rustix/fs/fn.flock.html). [Apple's flock manual](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/flock.2.html) describes advisory exclusion and the inherited-description unlock hazard. The implementation uses safe rustix APIs and validates the required directory locking behavior with subprocesses on this Mac; documentation alone is not a filesystem compatibility claim. No cryptography was added.

Run `cargo test --offline --locked --manifest-path experiments/rust-remote/Cargo.toml`, strict all-target Clippy, and formatting. The store adds 11 unit tests (including the private subprocess helper), one allocator test and one compile-fail doctest. At this descriptor-only checkpoint the crate had 147 tests and seven doctests. The authority follow-up and final v1 status spelling are documented in PERSISTENT-AUTHORITY.md. Existing six Node checks continue to cover transport/service contracts; the new disk format is deliberately incompatible with Node files. See RESTART-PROPOSAL.md for the exact Node inventory and authority follow-up.

## Separate gates

Persistent authority and its explicit close/retire guards are the next checkpoint; supervisor wiring follows separate review. Real asynchronous HTTP still needs atomic request Claim and bounded completion/cancellation. Duplicate owner DrainWork saturation of the reserved control lane, saturated carrier Disconnect admission, and dispatch fairness remain tracked P3 follow-ups; this store work does not claim to fix them. No live endpoint, existing data/profile, mobile/native fingerprint, production host, daemon lock or push is involved.
