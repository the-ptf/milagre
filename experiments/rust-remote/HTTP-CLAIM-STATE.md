# Private synthetic HTTP claim state machine

The concluded [contract](HTTP-CLAIM-PROPOSAL.md) now has a private `http_claim` module. It is a standalone fixture state machine, compiled with the crate and exercised by unit tests. It is not wired to Registry, TemporaryAuthority, PersistentAuthority, either supervisor, MemoryHttp or a network library. No public service command or production gate changed.

## Ownership and transition boundary

`Machine` serializes fixture operations through one mutex. `connect`/`admit` mint synthetic carrier/work tokens; they do not authorize real device records. Tokens bind to a retained scope and checked monotonically increasing serials. Replacement/removal invalidates the fixture generation, cancels its claims and refuses old tokens. Previous-machine scope tokens cannot enter a successor. This proves the model's transition rules, not persistence of real device epochs or atomicity with the existing authority.

`prepare_claim` reserves a status charge against the existing connection/device/global pool before populating a fixed table slot. The entire 512-entry backing table, work table, 16-device table, 16-entry command ring and bookkeeping are reserved before constructing the machine. A device may retain at most 32 status slots. Dropping a prepared attempt releases its exact slot; the borrowed work remains eligible. `submit_claim` consumes once, returns the same attempt on Full, and returns no retryable attempt on stale/expired/stopped refusal. Receipt destruction has no side effect.

`process_next` checks work/generation, scheduling expiry, checked deadline additions and executor capacity before reserving resources. It reserves the complete model resource allowance before allocating response storage and changing work to Claimed. A refusal records NotClaimed and permits a new attempt while that work remains eligible. Repeated accepted attempts for one work serial have one winner. Begin is the mutex-protected transition that records MayHaveRun and increments the **synthetic invocation counter** once. It does not invoke a callback or external operation.

Cancel, remove, replacement, stop and deadline processing use that same serialization. Cancellation before Begin retains NotStarted and zero invocations; cancellation after Begin retains MayHaveRun. The internal cancellation flag remains readable after owner status acknowledgment. Late completion cannot change a terminal state or produce another invocation. Unknown delivery is a terminal observation in this model; actually closing a Registry carrier and revoking its other work belongs to later wiring.

## Deadlines, storage and cleanup

Ready work expires at assembly/admission plus 20,000 ms. Claim starts 340,000 ms HTTP and 345,000 ms completion deadlines. Tick produces a modeled 504 state at the HTTP deadline and terminal expiry at the completion deadline; these are state observations, not encoded phone responses. Tick is explicitly driven by the fixture's manual clock. Automatic supervisor wakeups, actual 429/502/504 framing and the 45-second Registry idle deadline remain integration work.

Response storage uses 1,024 fixed boxed 64 KiB arrays and a fixed pointer table. All blocks are allocated after reserving their full charge. Append copies into existing arrays without Vec capacity growth, body reallocation or response-body duplication. Exactly 64 MiB fits; one extra byte selects the modeled 502 before any success delivery. Raw bytes are unchanged. Small state-transition tests use a private one-block constructor; the full-body and exact connection/device/global threshold tests use the full 64 MiB constructor. Rust allocator/process abort is outside the typed fault contract; Budget refusals and arithmetic failures are typed. Allocator implementation bookkeeping is not a measured physical-RSS guarantee.

The model additionally charges 64 bytes per body block, fixed resource metadata, a 2 MiB output allowance and 2 MiB scratch allowance before Begin. Those two allowances model prepaid resources; they do not yet reserve real Registry mailbox slots, codec estimates, HTTP library buffers or completion tasks. Real buffer/credit transfer must be proven at integration, against all other producers. Fixture devices/connections use 128 MiB budgets in the shared 256 MiB test pool, with two active resource sets globally and one per device. Removing/reconnecting a device retains its budget until its old leases drain.

Observation retention and cleanup are separate. `ack_terminal` hides observation but retains the slot and all resource leases while either executor or output cleanup is outstanding. The fixture's `cleanup` acknowledgments model those two independent owners; they are not real joins, socket receipts or authorization decisions. Terminal resources release only after both acknowledgments. Status acknowledgment before or after cleanup gives the same final accounting. Acknowledged/forgotten ids never become proof that execution did not happen.

`stop` cancels work without queue admission. `finish_stop` refuses until every modeled executor/output resource set is cleaned, then discards queued submissions and unobserved statuses. `quiescent` is a model assertion, not a persistent Clean receipt. The model spawns no owned background task, writes no persistent marker and adds no Drop-based clean commit. Real executor panic handling, retained joins and authority ownership continue to use the existing supervisor contract and require a separate composition checkpoint.

## Evidence and remaining work

Nineteen focused tests cover bounded preallocation, exact status release, 512/32 limits, Full retry identity, dropped accepted receipts, concurrent duplicate claims, deterministic barriers before/after Begin, acknowledged-status resource retention, full-size needed-minus-one/needed connection/device/global budgets, prepaid timeout progress under saturation, scheduling/claim/HTTP/completion deadlines, arithmetic overflow, fixed 64 MiB storage, removal/re-pair/replacement, unknown delivery, 1,000 device identities with bounded retained tables, two-global/one-device executor admission, stopped disposal old-scope refusal and skipped cancelled queue entries without lost readiness.

The full crate validation is 231 Rust tests and eight doctests, strict all-target Clippy and formatting. Existing seven Node reciprocal checks remain separate unchanged wire/source evidence. No new test claims real HTTP, actual phone interoperability, live service authority or persisted claim recovery.

Next checkpoint must compose this model with authoritative WorkToken/generation checks, consuming internal dispatch ownership, real request leases and mailbox/completion credits. Real HTTP dependencies and loopback carriers require their later reviewed adapter checkpoint. Reserved-control saturation, Disconnect admission/fairness, complete Unicode header/path compatibility, dense-state census, response batching, production endpoints/credentials/profile import, host lifecycle and mobile changes remain gated.
