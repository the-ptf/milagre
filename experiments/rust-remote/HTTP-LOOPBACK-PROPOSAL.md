# Private loopback HTTP execution proposal

Status: proposal for the checkpoint after `e5827fb733a50f231247bfd1d729674b32a28910`. No HTTP implementation, dependency, listener or production authority is added by this document. The accepted baseline remains 390 Rust tests, nine doctests and seven Node checks. This proposal has not run an HTTP experiment or established library allocation bounds.

Root and independent source review accept this direction. The next authorized work is the prerequisite dependency/allocation audit only. The private 128 MiB resource profile is an agreed design target, not an implemented counter change. No dependency addition, listener, HTTP Begin or production authority is authorized by this audit checkpoint; its results must establish the concrete bounds before the prerequisite implementation is accepted.

The next smallest useful execution slice is a real HTTP/1 exchange against a listener created and retained by the fresh synthetic authority, ending at **joined Ready** with the complete bounded response retained. It preserves the agreed 64 MiB response cap. It does not route through Node. It also does not claim phone delivery: **MaySend and Completed are unavailable for HTTP claims in this increment**. The current single fixed-frame delivery path must not be used to disguise that missing multipart integration.

Two local implementation commits form that checkpoint: first the private resource/claim/endpoint prerequisites, then real loopback execution and cancellation. Review the first before enabling Begin in the second. Full multipart delivery is the following checkpoint, with its required contract recorded below. All work remains in `experiments/rust-remote`; root owns commits and the migration index.

## Authority and endpoint construction

The new mode is crate-private, off by default and available only through the existing fresh `SyntheticProfile` capability and retained `PersistentAuthority`. Ordinary public `PersistentSupervisor::start`, fixed outcomes and MemoryHttp keep their existing behavior. No frontend type participates.

An illustrative `LoopbackFixture` is created inside authority startup after its backing reservation and writer admission. It binds exactly `127.0.0.1:0` itself. It retains that listener continuously until all authorized client work is joined, then joins its own server driver before releasing fixture ownership. Binding is explicit fixture setup; an individual request still makes no connection before Begin. There is one listener and at most two admitted server exchanges. Reuse/serial arithmetic is checked.

Only that constructor can mint an opaque, non-Clone endpoint registration bound to the authority instance, boot, listener generation and fresh synthetic test bearer. Its private address is copied internally into a claimed executor. There is no constructor from a URL, hostname, port, `SocketAddr`, listener, socket, file descriptor, profile path, token string, environment variable or arbitrary callback. The owner client receives only a scoped observation handle. No endpoint is serialized, exported to a normal command, persisted or registered with a production service.

The server accepts fixed private scenarios such as raw POST echo, an empty response, a chunk boundary, exact maximum, one byte over maximum, stalled head/body, truncation and malformed framing. Large responses are generated into a bounded scratch block, not retained in a second 64 MiB body. A bounded scenario enum supplies no arbitrary routes, byte scripts, response closures or file access. Requests are still encoded, encrypted and admitted through the actual synthetic phone Channel and Registry; a scenario selector cannot mint a WorkToken, approve a device or bypass quotas.

Use the literal loopback address and the exact live listener registration. No DNS, proxy discovery, redirects, connection pool, retry middleware, cookies, compression, TLS, HTTP/2, upgrades or HTTP/0.9. A redirect is observed as a response and never followed. The synthetic bearer is not a production credential or a defense against a hostile same-user process. Bound accept state and rejected-connection work prevent a local connection flood from creating unbounded tasks or retaining sockets. Holding the original listener prevents normal port reuse during this fixture; stale endpoint IDs never reconnect after teardown.

## Pre-Begin preparation and original admission

Keep the current 512 service/32 device status bounds, 16 rotating queued-device buckets, two retained execution slots globally and one per canonical device, including old generations still draining. Losing an accepted receipt permits observation/cancellation only. Full before enqueue returns the exact original attempt. Acknowledged or absent status is Forgotten/Unknown, never permission to replay.

Preparation must validate method/path/header representation and calculate a checked resource requirement without connecting. Preserve Node's eight blocked request headers and synthetic Authorization replacement. Permit GET and POST only; body bytes stay unchanged, and GET/empty POST omit a body. Reject unsupported request normalization before claim with a typed additional fixture refusal. Unicode/duplicate-header/URL differences must be recorded rather than called parity.

The actor remains the sole execution owner. At final claim it rechecks current policy, endpoint registration, exact target and WorkToken, scheduling expiry, resource grants and free core/device/server-exchange slots. A new private Registry operation moves the actual `LeasedRequest` into a non-Clone internal claimed request while atomically marking the job claimed. The Registry keeps the identity, deadlines and terminal control row. The retained core installs that request in a private shared allocation holder and keeps its own strong reference through actual worker join. Only a private worker read handle can share that allocation; the Reservation is owned once inside it, and no caller can clone/export the handle. Dropping the Registry job or unwinding the worker cannot refund the upload while the core's holder remains. The worker gets no Registry reference, profile or arbitrary request-export callback. No uncharged body clone is permitted.

Preallocated response blocks and transport backing use the same retained-owner rule: the core owns the allocation holder outside worker unwind. The worker has bounded private access; any mutable staging lock covers only a bounded copy, never IO or a wait. HTTP request-body adapters borrow from the retained request or copy one bounded prepaid chunk; no alias or connection future can escape the worker's owned runtime. Result publication does not transfer cleanup authority. On panic or cancellation, the core keeps all holders until JoinHandle consumption proves that every worker-local adapter/future/alias has been destroyed, then releases or retains the joined response according to its state.

Build the bounded request plan, response blocks, completion/cancellation cells and dormant worker before final claim. On pre-claim failure, cancel and join the dormant worker, release all exact grants and leave still-eligible work unclaimed. Poison/panic during that cleanup is sticky Abort. Once a claim exists, a failed Begin terminalizes that exact claim after real cleanup; it never restores Ready or presents the failure as NotClaimed.

The resource profile is selected privately before any session/device counter exists: **128 MiB per connection/device, the same original 256 MiB service GlobalBudget**. Ordinary service defaults stay 64 MiB. Removed/reconnected device counters remain alive with their old leases. The fixture may not instantiate another GlobalBudget to make admission pass. Server backing is reserved from that same service pool before listener/task creation; request-dependent accepted-socket work is bounded and paid before admitting the client claim. Each claim reserves an exact generation-bound server slot before Begin, including its canonical device identity. A client that finishes or is disposed cannot free that slot or its original budget lease while the server exchange still owns a socket, body reader or response future. New claims count those draining server slots against both the same two-exchange global bound and the one-active-per-canonical-device bound, including replacement/re-pair generations. A free client core cannot bypass a still-draining server exchange for that device.

Use one retained server-driver thread with two inline exchange cells rather than spawning per accepted request. Bind a request to its reserved server slot with a fresh private synthetic per-claim bearer minted before Begin; the listener accepts it once, and the caller cannot supply or replace it. This is fixture authentication metadata, not production bridge-token compatibility. The driver destroys an exact cell's socket/futures before publishing its private completion receipt; only reconciliation of that exact receipt returns the claim's server slot/charge. If the driver panics, retain every unresolved cell charge until actual driver join. Client completion, a status boolean or a cancellation acknowledgment is not server-cleanup proof. Rejected/unmatched sockets use only the prepaid bounded accept cell. Synthetic test-driver buffers must be counted separately in memory evidence, not mistaken for service allocations.

The complete reservation is one checked requirement split into owned subleases without release/reacquire. Library lazy allocations after Begin are permitted only inside a source-audited prepaid maximum; this is an explicit difference from the fixed worker's allocation-free execution path. No new pool reservation, Vec growth beyond charged capacity, response duplication or output-credit acquisition may be necessary after Begin. A numeric allowance without source and allocation evidence is insufficient. If the complete maximum cannot fit the agreed fixture pool, refuse before claim or revise the design; do not reduce the 64 MiB cap silently.

The first prerequisite commit implements the real output grants even though the execution increment cannot emit. An exclusive exact-carrier egress fence can remain the conservative initial policy: unrelated producers on that carrier refuse before sealing; other carriers and ingress continue. That restriction must be explicit. The existing one-frame `reserve_fixed` flag is not evidence that the larger count/byte window was reserved. Cancellation returns unused grants by ownership, without inventing a Packet receipt.

## Exact Begin, cancellation and deadlines

Begin uses the accepted lock order: current Registry/session access, cancellation gate and final owner queue transaction for inline evidence only. Resample the shared service clock at that final transaction. Check current endpoint/claim identity, RUNNING stop, sticky failure, cancellation and the minimum effective job, idle, reader-fragment and HTTP deadline. Equality refuses. Record MayHaveRun and open the worker's gate atomically. Do not hold any of those locks across connect, write, read, allocation or join.

Only the retained worker can consume that gate. Its first externally visible client action is one connect to the registered address, then one request. Connect failure consumes the operation after Begin; it cannot trigger reconnect/retry. Cancellation observed before Begin means NotStarted and zero client connections. Cancellation after Begin always retains MayHaveRun, including a barrier before connect or first write. A cancellation check immediately before a write narrows the race but cannot establish that an already-authorized request had no effect.

Cancellation is prepaid and out of band. Removal/replacement/retirement/disconnect/stop invalidate the exact identity and signal the worker; a full command, approval or event lane cannot prevent an already-applied cancellation. The worker selects cancellation/deadline against connect, write, response head and body reads. Its retained cancellation cell stores the async runtime waker: each pending cancellation poll registers the current waker under the cell's synchronization, then rechecks cancellation/deadline before yielding Pending. Cancellation sets the state and takes the registered waker under the same protocol, including cancellation before registration, then wakes it after releasing the lock. The server-driver cell has the same protocol. Owner Thread::unpark/WakeToken is a separate progress path and does not substitute for waking either async IO driver. Waker registration and retained storage are prepaid; exact disposal clears registrations after future destruction so stale wakes cannot act on a reused slot.

The worker drops the active HTTP futures and closes its owned stream, then exits. Cancellation signaling alone, stream close, EOF, result publication and `is_finished()` are not Joined evidence. No socket IO task may be detached behind the result. A deterministic register/recheck race test must cover cancellation immediately before registration, between registration and the recheck, and after Pending, with client and server stalled on IO and no later traffic.

All deadlines use the same service time base: assembly +20,000 ms for Ready; claim +340,000 ms for HTTP; claim +345,000 ms for completion. Claim preparation and Begin delay never reset them. Worker deadline wakeup and the owner's existing bounded tick must agree with that clock; no unrelated wall-clock timeout may extend the deadline. At HTTP equality, request cancellation and retain a 504 only after real join, while the completion margin remains. Completion equality expires and discards pending output. The normal 45-second idle deadline remains; timeout tests keep it alive with ordinary encrypted traffic. Clock regression, overflow and poisoned synchronization retain sticky Abort and the original writer.

Rust actively cancelling the socket differs from Node's active-fetch disconnect behavior. No test should claim cancellation reverses a POST. The server's observed side-effect counter and client invocation evidence are separate; either uncertainty prohibits replay.

## HTTP parsing and retained Ready

A candidate locally available stack is pinned Hyper `=1.12.0` using only `client::conn::http1` over an already-authorized stream, with a retained current-thread runtime/IO bridge. This is a dependency proposal, not a completed selection. Exact supporting versions/features and lockfile checksums must be pinned during the prerequisite review. There is no high-level URL connector or Reqwest client. Drive the connection future and exchange inside the same retained worker; do not follow examples that spawn an unowned connection task.

Local primary-source inspection found `Builder::max_headers`, `max_header_size` and `max_buf_size`; it also found that `read_buf_exact_size` and `max_buf_size` unset one another, parser/header-map allocations, and `BytesMut::reserve` in the IO path. Therefore builder settings alone do not establish retained-capacity bounds. Audit allocation rounding, header/trailer storage, read-ahead, queued outgoing body frames, informational responses, runtime driver storage and cancellation/drop behavior. Clamp reads at the adapter boundary where needed. Propose at most eight informational responses with 64 KiB aggregate informational heads, 100 trailer fields/64 KiB trailer bytes and 72 MiB total inbound HTTP bytes (64 MiB data plus at most 8 MiB head/framing allowance). These are additional fixture restrictions; exact boundary tests must show where violations select 502. Cap work per connection poll and yield between bounded operations so repeated 1xx or chunk extensions cannot starve cancellation. This review must close before real Begin is admitted.

## MaySend and the following delivery gate

For this execution checkpoint, HTTP claims have no transition to MaySend: neither `emit_fixed` nor the fixed 200 encoder accepts their result type. Both success and 502/504 remain joined Ready. Tests must assert zero response seals and zero Completed states. This explicit limit avoids proving delivery only for tiny responses while calling the 64 MiB contract complete.

The following checkpoint must encode one 256 KiB raw part at a time from retained blocks into the prepaid window. Before the first seal, MaySend must revalidate the exact Registry/session/owner/endpoint lifetime, cancellation and effective completion/idle/fragment deadline in the existing final transaction. Every later part gets the same exact-identity/deadline checks. Do not hold owner locks during crypto or mailbox IO.

Each part needs an exact claim/part/slot-generation receipt. Reuse a window slot only after its actual Packet destruction and non-Clone returned credit. Authenticated synthetic-peer acceptance must compare the real expected part bytes, status, headers, index and `more`, not just a success flag or digest supplied by the caller. Completed requires all parts accepted and returned, actual executor join and the current final authorization transaction. No early Completed on the first part, writable socket, body EOF or observer acknowledgment.

After MaySend, cancellation, expiry, failed verification, lost sealed bytes or unknown write closes and physically drains only the exact old carrier. Retain Unknown and MayHaveRun, discard remaining parts and never emit a replacement 502 series or retry HTTP. Before MaySend an error can select its prepaid 502/504 only if the claim is still authorized and before completion expiry. The real HTTP connection and synthetic encrypted peer are separate ownership domains; successful HTTP exchange is not phone receipt.

## Join, shutdown and acceptance evidence

The retained core owns every client JoinHandle, socket/runtime owner, request lease and completion slot. Normal actor turns only join finished handles and remain bounded by two entries. Slow connect/read never blocks the owner. Result/wake publication precedes physical thread exit in a test barrier; charges remain until the real join. Stop cancels all client work, joins it, drains retained response/output ownership, then stops/joins the fixture listener and its bounded server work before authority Clean persistence. No clean proof is synthesized from counters. Panic/poison/unknown cleanup returns the existing typed retained failure with the original writer, even if subsequent drainage succeeds. Drop never writes Clean.

Required acceptance groups for the next checkpoint:

1. **Capability and real wire.** Compile-fail privacy checks for endpoint/socket/URL/credential construction and public supervisor access. Actual synthetic Channel to Registry to HTTP GET/nonempty POST/empty POST; listener-observed exact raw body/hash and header policy. Every destination equals its owned literal ephemeral listener. A second synthetic listener receives zero requests from redirect responses; no arbitrary-port test uses production sockets. Endpoint loss, stale boot, replacement and re-pair refuse without connecting. Inject bind/runtime creation/server-driver spawn failure and panic after writer acquisition and after listener creation. Each path must close/join only its owned resources, leave no socket/task detached and return the original retained writer failure; it cannot invent Clean or reopen the profile.
2. **Claim and cancellation races.** Deterministic barriers before claim, before final Begin, after Begin before connect/write, after the server records a side effect, during headers/body and after result publication before thread exit. Repeat cancellation/removal/replacement/stop at each barrier. Assert zero versus one Begin/connect/request counts correctly, no reconnect, one join, retained MayHaveRun after Begin, stale completion isolation, no successor damage and exact request/output/resource refunds. Duplicate WorkTokens and dropped accepted receipts yield one winner. Delay physical client and server exit separately; Clean/writer release waits for both.
3. **Deadlines and actor progress.** Scheduling, Begin, HTTP and completion equality, idle/fragment minima and rollback/overflow. Keep normal idle traffic alive for the 340,000 ms timeout. 5. **Compatibility and regression.** Keep all existing 390 tests/nine doctests and seven Node checks. Add actual local Node `fetch` traces against a separately owned synthetic scenario listener, without importing service startup or reading profiles, for the exact HTTP subset claimed. ## Deferred gates and authorization limits

Multipart MaySend/acceptance/returned-credit/Completed integration is the immediate next gate after this execution slice. General shared mailbox coexistence beyond the conservative exact-carrier fence, unclaimed scheduling-expiry 429 output, 400/413 compatibility, saturated RemoveDevice/Disconnect admission, the combined continuous-replacement fairness test and dense JSON/complete Unicode/URL/header normalization remain explicit gaps. This proposal does not lower the 64 MiB response cap or raise ordinary service limits to bypass them.

Production bridge route registration, real profile/credential adoption, production endpoint grants, relay/LAN networking, HTTP feature expansion, restart/durable deduplication, provider execution, live phones and host cutover require later contracts and evidence. The synthetic listener grants none of those. Do not push, restart the installed host, touch live profiles/credentials, change mobile, add another Project writer, or wire either Tauri or GPUI. Completion of this proposal or its loopback checkpoint is not removal of the production Node daemon.
