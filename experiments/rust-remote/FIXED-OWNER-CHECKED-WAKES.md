# Private fixed owner checked wakes

This is the checked-wake-only portion of [increment 2B.3](FIXED-OWNER-DELIVERY-PLAN.md), following [the accepted lifetime amendment](FIXED-OWNER-WAKE-LIFETIME.md) and delivery checkpoint `9f91940e`. It preserves the existing submission ring and command priority. Rotating buckets, a control-plus-ordinary fair round and the sixteen-visit fairness guarantee are not implemented. Ordinary public service keeps its existing Condvar loop; only the fresh private fixed fixture uses the checked wake hub. No frontend, network, HTTP, provider, production/existing-profile or mobile authority is added.

## Wake and park protocol

One run-owned hub contains checked AtomicU64 generation, sticky overflow, the actor Thread installed before startup acknowledgment and Weak Shared. Input mutations publish first, then increment generation with checked CAS and unpark. Command/control/approval admission, private operations, cancellation/unsubmitted Drop, stop/failure, actual worker return/unwind and actual Packet Drop all reach this route. Status/event observation and unchanged maintenance notify their existing waiters without incrementing generation.

Overflow never wraps. It sets the latch, publishes the original first fault and Abort using a separate atomics-only function, then directly unparks. An already-latched wake republishes failure without incrementing generation. This path takes no queue, Registry or session lock, including when its caller holds one. Final admission checks follow preparation and precede enqueue/permit consumption. Private operation dispatch rechecks after maintenance; carrier adoption rechecks before registration and again under the queue before publishing its target/roster, closing the exact carrier on late refusal. Begin, MaySend, authenticated acceptance and Completed recheck the latch inside their existing final queue transaction. Shutdown recognizes the brief latch-before-Abort interval as WakeOverflow instead of InvalidExit.

The fixed actor samples generation before each bounded round. It runs existing maintenance/delivery, at most one existing priority command, one private operation and existing ring selection. Afterward it checks queued commands/operations, unapplied cancellation and eligible submissions with a free core under the queue mutex. It releases that mutex, rechecks stop/latch/generation, then parks only if idle and unchanged. An unpark after the last generation check retains its token across the gap. The unchanged 1..100 ms tick handles deadlines and a worker wake that precedes actual thread exit.

Unfinished children, peerless Ready, delayed returned credit and submissions blocked by an occupied same-device core alone allow parking. Wakes are progress hints only. Actual join, authenticated verification, Packet Drop credit and exact disposal retain their earlier evidence requirements.

## Prepayment and lifetime

Worker and packet tokens are immutable Weak hub references prepared before Begin inside the unchanged claim allowances. A stack guard wakes on worker return or panic, before the thread necessarily finishes. Packet Drop frees ciphertext and its moved lease, publishes real returned credit, then wakes and drops its token. No receipt cell or public handle receives a Weak hub token. A test assertion checks that internal tokens are gone while a run strong reference still exists; actual join/packet drainage remains the cleanup proof.

The measured 64-bit hub is 40 bytes. Its conservative Arc allocation is 63 bytes; the surviving local budget Counter Arc is 55 bytes, for an exact **118-byte retained reservation**. Option<WakeAccess> is 48 inline bytes. The hub/counter split and access representation fit the existing 4,096-byte backing slack. The split is taken once from the original startup backing before hub allocation/writer acquisition; no resource allowance or global pool is replaced or increased.

Test layout is State 235,776 + RuntimeFixed 5,768 + 4,096 = **245,640 gross prepaid bytes**, with 245,522 in State and 118 in Shared. The separately compiled non-test layout is State 202,992 + RuntimeFixed 5,768 + 4,096 = **212,856 bytes**, split into 212,738 and 118. Row is 440 bytes with test hooks and 376 without them. Compile/test pins verify these layouts. Status remains 2,048 bytes, peer/registration 4,096 each and tracked claim 2,172,416.

After joined shutdown, old strong owner/carrier clients intentionally retain the 118-byte charge. Final Shared payload Drop removes its immutable weak hub slot before releasing that reservation. Weak-only clients/approvals do not retain a live hub link after Shared destruction. The hub's Thread and Weak Shared payload drop at the final strong hub release, which can follow a transient public wake upgrade; that upgrade keeps Shared and its charge alive. Inline Shared weak-allocation tails retain the explicitly disclosed existing accounting boundary, rather than a new complete physical heap claim.

## Registry expiry and evidence

Registry remains the source of timeout evidence. Duplicate preparations remain possible: if one attempt claims a token, its extended Registry lifetime can leave another Prepared/Queued observation visible beyond its original scheduling deadline. The losing row cannot execute alongside that same-device core. It can park, then becomes stale/terminal after the real claim ends without replay or a false promotion. This checkpoint adds no independent attempt-expiry policy.

Six primitive tests cover checked/coalesced generation, preinstallation publication, one-time Thread installation, overflow with a held queue guard, normal/unwind stack notifications, retained unpark across the final gap and exact charged weak-tail refund.

Twelve actor tests cover both scan/park gaps; parking with unfinished/Ready/AwaitingReturn or duplicate blocked work; worker wake before actual exit; exact 118-byte old-client retention and final refund with old weak handles; all four final commits and command/control/approval/private admission with an independently latched overflow; Packet-return overflow under session access with real refund and retained writer; verified/unverified return wakes; progress with full ordinary/control/event lanes; pre-writer refusal cleanup; and overflow during private adoption maintenance before registration. Existing startup panic/spawn failures, ordinary service, scoped Claim, delivery, expiry and joined-shutdown regressions remain included.

Its failure guard requests Abort and directly unparks; a final running check closes the cleanup/token-drain gap.
