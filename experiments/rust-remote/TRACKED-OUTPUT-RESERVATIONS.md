# Checkpoint 2, reservation and fence boundary

This first implementation commit establishes admission ownership only. It does not emit or consume tracked packets, verify a synthetic peer, publish packet-drop receipts or mark tracked work Completed. Those operations and failure/physical-closure composition remain the next implementation stage of [the agreed contract](TRACKED-OUTPUT-CONTRACT.md). No supervisor command, owner queue, scheduler, HTTP adapter or public client API is added.

`register_fixed_carrier` installs at most 16 authority-owned exact-generation targets. Registration validates a fresh unbound mailbox, atomically binds its access guard and target identity, and retains a separate 4,096-byte original-session reservation until exact carrier closure or authority drainage. Static mailbox capacity below one frame or 1,024 wire bytes refuses before binding.

`start_fixed_tracked` reserves 2,172,416 bytes from the original connection/device/global budget before allocation or spawn, then splits the charge without releasing counters. The charge covers the existing execution and metadata, 65,536 bytes for encoding/verification scratch, 1,536 for one ciphertext packet, and 2,048 for grant/receipt bookkeeping. All three fixed 200/502/504 response encodings are prepared before Begin. Vector capacities plus explicit codec/verification headroom are checked against the scratch allowance.

One exact target/claim grant fences Registry and mailbox egress. Its sole owner releases both capacity grants on pre-Begin rollback or slot disposal. Same-carrier Send, send_peer, Finish, MemoryHttp, scoped Claim output and generic output export refuse outside the protocol-failure wrapper. Ordinary mailbox delivery refuses and receive cannot skip the fence. A refusal invokes no fake, seals no frame and leaves eligible sibling work and the carrier active. Other carriers and incoming traffic remain independent.

Three added tests establish connection needed-minus-one/exact admission, unclaimed work and zero retained slots on budget refusal, invalid mailbox limits without binding, already-bound/foreign target refusal, prior Registry-output refusal, fence coverage for Send/send_peer/Finish/MemoryHttp/export/ordinary receive, zero fake invocations, successful subsequent consecutive-channel output after disposal, and refusal of an inactive rolled-back fence even when a retry reuses the same claim serial. Existing scoped Claim tests remain unchanged. Immediate physical-mailbox reconciliation after Registry failures/timeouts in forwarding calls remains stage 2 work; explicit disconnect/removal/replacement and authority drainage reconcile already. Direct ordinary-mailbox delivery, shared-device/global pressure, packet receipts, verification, delayed acceptance, unwind and post-MaySend closure tests are not claimed by this first boundary.

Validation at this boundary: 282 Rust tests, 8 doctests, strict all-target Clippy, formatting, example builds and all seven unchanged Node reciprocal/source checks pass. Fixtures use fresh marked synthetic profiles and synthetic keys only; no network, production data or real-phone interoperability is exercised.
