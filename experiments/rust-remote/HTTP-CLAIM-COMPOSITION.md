# Private authority and joined-worker claim composition

This checkpoint connects a bounded fixed-response fixture to actual `PersistentAuthority`, Registry work, authorization guards, channel encryption and shared budgets. It adds no public supervisor command, HTTP dependency, socket, arbitrary URL/closure, existing-profile constructor or mobile change. Construction uses an existing fresh synthetic authority capability. The standalone full-body claim model remains separate.

## Scope and capabilities

`policy::persistent::claim_worker::Prepared::new(&mut authority, WorkToken, Clock)` checks policy/Registry readiness and the actual token's identity, generation, state and assembly-time scheduling deadline. It reserves metadata from that session's existing connection/device/global budget. It borrows the authority exclusively. Dropping an unsubmitted Prepared returns that charge and leaves eligible work unclaimed.

`Prepared::with_claim(Outcome, callback)` accepts only fixed synthetic Success, Unavailable, Timeout or a test panic. It reserves a 2 MiB thread stack allowance, 64 KiB fixed-output/scratch allowance and bounded bookkeeping before spawning a gated worker. Full returns the original Prepared, including its metadata lease; it neither claims the work nor invokes the fixture. Spawn or final claim refusal retains the original borrowed authority, and any already-created worker is cancelled and joined before the refusal returns. Other refusals are not permissions to replay an accepted operation.

Only after reservation and spawn does Registry mint the non-Clone `Permit`. Its WorkToken retains the original registry/authority/boot/device epoch and carrier/work serial binding. Claimed jobs disappear from read-only DrainWork and reject ordinary finish, duplicate claim and MemoryHttp dispatch. Normal jobs keep their existing behavior. The assembly-plus-20,000 ms scheduling deadline does not reset on promotion. Claim uses one current clock sample for its 340,000 ms HTTP and 345,000 ms completion deadlines. Clock reads happen inside the exclusive authority operation.

This first composition borrows one authority for one claim at a time. It requires an empty outbound queue and supports one encrypted response frame of at most 1,024 bytes. The exclusive borrow prevents competing output producers from consuming its reserved slot. These are private fixture restrictions, not the completed two-global/one-device asynchronous scheduler or 64 MiB HTTP adapter. Existing 64 MiB service budgets remain unchanged; the agreed 128 MiB fixture configuration and full-body model are not silently substituted into the service.

## Begin, join and output evidence

Begin checks the actual claim under Session's current authorization guard, then sets MayHaveRun and opens the worker gate under the cancellation mutex. Cancel before Begin leaves NotStarted and zero fixture invocations; after Begin, cancellation never restores that evidence. The worker runs only a fixed outcome and waits on an owned cancellation/completion signal. Its completion signal controls fixture timing and is not evidence of a join. `collect` refuses while completion is pending; it does not block the owner waiting for a timer or external event.

`Joined` is private and constructed only by consuming `JoinHandle::join`. Executor reservation release follows the actual join. Worker panic is joined and calls `authority.abort_in_place`; the existing typed close failure retains the writer and cannot return Clean. Drop cancels and joins a worker waiting before Begin or after its synthetic invocation. No worker or reap thread detaches.

A joined result records status 200, 502 or 504 independently of execution and delivery state. Fixed 502/504 bodies come from the existing Node-compatible response mapper. `may_send` checks authority and deadline again and marks MaySend under the same final authorization guard that seals the first response frame. It splits the final ciphertext lease from the pre-invocation reservation and transfers bytes plus lease through Registry's owned-output path. No post-invocation budget acquisition is needed for this fixed response.

The private output slot returns an `OutputLoan`, which borrows the Claim and therefore the authority. Its bytes remain charged while held. Packet's own Drop destroys its bytes and reservation, then sends a non-Clone `ReturnedCredit` through its unique bounded return channel. The receipt type's constructor is private to that module; adjacent cleanup code cannot mint it. No caller supplies an output-done boolean. Only this return plus a real Joined proof can satisfy the cleanup diagnostic. Returned means a successful `bytes()` call exposed ciphertext to the in-memory reader before ownership returned, not that a phone acknowledged delivery. A normally dropped loan without any successful `bytes()` call is Discarded, with the work Cancelled rather than Completed. Execution remains MayHaveRun, status remains available, and neither outcome permits replay. Status remains observable after return. Unknown delivery, removal, completion expiry and idle expiry after MaySend preserve Unknown rather than reverting to None.

A held output loan checks the current Registry authorization/idle/request deadline before exposing bytes and on return. Expired reads refuse, and the packet remains charged until its loan drops. A caller holding that scoped loan prevents mutable authority operations by construction. This is a trusted in-memory fixture boundary, not a production concurrent socket-reader API.

`Prepared::with_claim` retains the owning Claim in its own stack frame and passes only a higher-ranked mutable reborrow to the callback. The owned constructor is private. Neither the Claim nor an output loan can escape through the callback result. Forgetting the reborrow or an output loan leaves the owning Claim available for cancellation, actual join and output drainage when the scope returns or unwinds. An exclusive borrow by itself was insufficient because `mem::forget(Claim)` could previously end it without Drop. There is no boolean clean/join assertion, force close or persistent Clean receipt in the composition. Existing supervisor retained-worker/CloseFailure semantics remain unchanged.

## Scoped retention safety checkpoint

The public-to-crate entry is now `with_claim`, which retains worker ownership outside caller control. Full still returns the original Prepared. Four deterministic forget paths (before Begin, running, after MaySend, and a forgotten output loan), callback unwind through a held loan, and a worker-panic accounting test verify real join/lease release before terminal authority close. The execution reservation now stays in OwnedWorker until JoinHandle::join returns, including panic, rather than unwinding inside the worker. This checkpoint changes no scheduler or network surface.

## Packet-return evidence safety checkpoint

The packet owns the only sender for its per-claim receipt channel. The channel is allocated before Begin under prepaid resources; 2 KiB of metadata charge retains the bounded channel/signal after output and executor leases release. A unit test verifies the receiver remains empty while bytes and the whole charge are owned, and sees a receipt only after both are destroyed. Cancellation before packet creation releases unused prepayment without inventing a receipt. Loan discard, scoped forget and unwind paths remain covered. Cancellation or expiry after MaySend remains conservatively Unknown; ordinary unread loan return is explicitly Discarded.

## Ready expiry safety checkpoint

Private claim admission now distinguishes `AdmissionError::Expired`/`Fault::Expired` from generation or authorization refusal. Inspection at or after assembly plus 20,000 ms removes the exact unclaimed job as TimedOut, releases its in-flight slot/body charge, and promotes eligible queued work. A still-current token already timed out by Registry tick also reports Expired. Superseded or revoked bindings remain Stale.

Successful inspection shortens that candidate's deadline to the original scheduling boundary, so the existing periodic Registry tick also expires it if a Prepared permit is dropped or held. Reinspection never renews it. Actual claim replaces it with the agreed claim-relative completion deadline. This opt-in change leaves uninspected legacy MemoryHttp work on its existing lifetime. No scheduler, automatic retry or 429 response encoder is added; scheduling expiry is terminal state/resource cleanup, not a new phone-response compatibility claim.

Four regressions cover first inspection at equality, queued promotion and charge release, periodic expiry after dropped/repeated preparation, held-permit expiry without invoking the callback, and successful execution one millisecond before equality. The safety chain adds three retention tests, three packet/receipt tests and four expiry tests to the original 244-test baseline.

## Lost sealed output safety checkpoint

Sealing advances the channel's send counter. The peer accepts only its next consecutive counter; destroying a sealed frame and keeping that carrier alive would make all later output fail with `Error::Order`. The sealing contract is unchanged. Any post-MaySend discard or unresolved delivery closes that exact carrier with `CarrierFailure` if it is still current. Existing removal, replacement or timeout closure reasons remain intact. Registry removes the claimed job with its terminal status before closing, without promoting work on the broken carrier; closure cancels the carrier's remaining jobs and drains queued bytes. Other carriers remain usable.

An unread normal loan drop retains `Discarded`, MayHaveRun and the HTTP status, marks work Cancelled, and closes the carrier. Cancel, expiry, forgotten loan, scope exit with outstanding output, and unwind through a held loan retain Unknown delivery. A reader unwind remains Unknown even if `bytes()` was called before the panic. Packet destruction still issues the actual credit receipt, and the owning scope still joins before authority terminal close. If sealing succeeds but transfer into the output slot fails, cancellation closes the carrier and drains the already-sealed queued frame. No cancelled response can leak into a later dispatch. Cancellation before MaySend leaves an otherwise valid carrier active.

Normal exposure followed by normal loan return retains Returned/Completed and a usable carrier. This is only the trusted in-memory reader's handoff convention, not proof of phone delivery: a caller that reads bytes and silently drops them violates that convention. Real transport write/ack evidence remains an adapter gate. Callback observations copied out before scope exit describe that earlier moment, not later Drop effects. Forgotten Prepared metadata has the same intentional-leak limitation as any forgotten Reservation; it owns no worker or packet.

Two new tests cover actual peer counter rejection after a skipped frame and eight carrier-loss paths with retained status, no replay, joined cleanup, credit release, and continued encrypted traffic on another carrier. Existing response tests now decrypt consecutive responses on the same carrier. The separate panic-credit regression waits for `JoinHandle::is_finished()` before checking that execution credit remains charged until join, so a fully unwound worker cannot make it pass accidentally. These fixtures use no HTTP, production profile, network or mobile changes.
