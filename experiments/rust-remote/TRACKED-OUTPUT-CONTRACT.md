# Checkpoint 2: private tracked fixed output

This document records its original checkpoint boundary. [Increment 2B.2 delivery evidence](FIXED-OWNER-DELIVERY.md) describes the later private actor integration; peerless Ready and public-service boundaries remain intact.

Status: agreed refinement of checkpoint 2 in [FIXED-CLAIM-SUPERVISOR-PROPOSAL.md](FIXED-CLAIM-SUPERVISOR-PROPOSAL.md). Checkpoint 1 and its failed-Begin fix remain the baseline. The [reservation/fence implementation boundary](TRACKED-OUTPUT-RESERVATIONS.md) and subsequent [packet/verifier/physical-close composition](TRACKED-FIXED-OUTPUT.md) are implemented and tested separately. Independent review remains a gate before checkpoint 3. This contract does not enable a public admission gate. Only fixed 200/502/504 responses, synthetic keys and fresh marked profiles are in scope. No owner queue, automatic scheduler, public client API, HTTP or network adapter is added. Existing scoped Claim behavior remains independently tested.

## 1. Internal ownership and API

The authority owns a bounded table of at most 16 registered fixed-output targets, one per exact current carrier generation. Proposed private `register_fixed_carrier(handle, fresh_memory, mailbox_limits) -> TargetId` requires an Active Registry handle and a fresh, unbound, empty MemoryCarrier. It binds the current authorization guard and an immutable identity containing authority instance, handle generation and target serial. Already-bound or foreign mailboxes refuse. Validate static limits and identity before binding; a failed bind retains no registration or charge. It charges registration before allocation, retains a physical-close capability, and returns only an opaque, non-owning identifier. Registry closure removes that exact registration and releases its charge; slot reuse gets a checked new serial. External MemoryCarrier clones never own the authority's worker, packet receipt or writer. This separate registration is necessary because today's mailbox has no carrier-generation identity. Reusing the supervisor's already-bound mailboxes is later integration work.

`start_fixed_tracked(token, target_id, outcome, clock) -> Result<Id, Fault>` reuses the retained two-slot core. Token and target must name the same current carrier. All output resources and fences are installed before spawn/claim/Begin; every refusal or unwind rolls them back with exact identity checks. The fixed-start failed-Begin cleanup still joins and refunds before returning no Id. Existing `start_fixed` stays output-free.

`emit_fixed(id)` is explicit, private and single-shot. It requires an actually joined Ready result, current authorization and unexpired completion deadline. It seals one fixed frame and transfers it through the reserved Registry slot into its bound mailbox. `consume_fixed(id, &mut synthetic_phone_channel)` is an authority operation that validates and consumes that packet internally. It returns only fixed-size request-id/status metadata. Neither method exposes a packet, byte slice, receipt constructor, arbitrary closure or mutable worker. Poll/tick/discard/close process bounded receipt and target cleanup; they do not automatically start work or pump output. No external `ack_terminal` API is introduced.

Registration has its own 4,096-byte connection/device/global lease, retained until exact-carrier close or authority teardown. The registration table is fixed-capacity; no unbounded map is introduced. Targets and claims share the original session budget handles. Tests pin the inline entry/ledger/Arc bookkeeping sizes within this allowance. Failure to fit is a refusal before allocation, never a silently larger allowance.

## 2. Prepaid capacity and competing producers

For an already registered target, the proposed charge per tracked claim is:

| Reservation                                       |         Bytes | Lifetime                                                                      |
| ------------------------------------------------- | ------------: | ----------------------------------------------------------------------------- |
| Existing execution stack/bookkeeping              |     2,101,248 | Through actual worker join                                                    |
| Existing core metadata                            |         2,048 | Through claim disposal                                                        |
| Encoding, verification and fixed-response scratch |        65,536 | Through encode/consume or cancellation                                        |
| Ciphertext plus packet allowance                  |         1,536 | 1,024 maximum ciphertext + 512 bookkeeping, through actual packet destruction |
| Output grant and bounded receipt bookkeeping      |         2,048 | Through final receipt processing and disposal                                 |
| **Total**                                         | **2,172,416** | Output adds **69,120** to checkpoint 1                                        |

Target registration is separate: a fresh target plus one tracked claim requires 2,176,512 bytes beyond existing carrier/request charges. All additions and counts use checked arithmetic. Reserve the full tracked-claim total atomically from the original connection/device/global budget, then split reservations without releasing/reacquiring counters. The 64 MiB connection/device and 256 MiB global defaults remain unchanged. These are accounting allowances, not process-RSS guarantees.

Before Begin, precompute and validate the three possible fixed response encodings using the existing Node-compatible mapper. Each must fit 999 plaintext bytes, hence at most 1,024 sealed bytes. Allocate bounded receipt storage and all persistent slot/container backing under reservation before Begin. Charge vector capacities, not just lengths; assert aggregate preencoded/codec/verification capacity stays inside the 65,536-byte allowance. Crypto/verification temporary allocations after Begin remain covered by that retained allowance. Allocator/process abort stays outside typed failure recovery.

Admission requires both prior Registry output and prior mailbox output to be empty. Reserve one Registry frame slot plus 1,024 wire bytes and one mailbox frame slot plus 1,024 wire bytes. These are two queue-capacity reservations, but the frame's 1,536-byte memory lease moves between owners and is charged only once. Use dedicated tracked storage, avoiding an unreserved VecDeque growth during transfer. Effective capacity is ordinary occupancy plus reserved tracked occupancy; storing the tracked frame does not count it twice. Both capacity grants and the egress fence remain held until packet-return processing, or exact close.

The fence is bound to authority/carrier/claim serial. All same-carrier output producers and export paths must honor it: Send/send_peer, Finish, MemoryHttp dispatch, scoped Claim emission, ordinary mailbox deliver and generic Registry take-output. Refuse before sealing, fake invocation or byte export. A normal fence refusal returns Budget/Full directly, outside the protocol-failure wrapper, so it neither closes the carrier nor consumes eligible work/MemoryHttp. Ordinary receive cannot pop or skip tracked output. Incoming traffic, keepalives, cancellation and other carriers continue. The tracked output path makes no new memory-budget reservation, queue-capacity acquisition or receipt allocation after Begin; unrelated admitted input retains its existing accounting. Saturating every unreserved byte afterward cannot prevent the fixed result or fixed error from using its prepaid path.

## 3. Delivery evidence, lock order and closure

MaySend is recorded under the final authorization guard immediately before sealing. Queuing or reading bytes is never Delivered. `consume_fixed` checks identity and the retained clock/deadline, obtains the exact session access guard, and opens the whole ciphertext with the actual synthetic peer Channel. It compares the recovered bytes to the prevalidated selected fixed response, then drops the plaintext internally. Only that successful verification can construct a private PeerAccepted marker. A mismatched channel, failed open, skipped consume, ordinary drop or unwind cannot construct it. Recheck time before recording acceptance; equality expires. This is synthetic peer acceptance, not socket or real-phone acknowledgment.

The mailbox owns the packet; the authority retains its close capability throughout. Packet Drop first destroys ciphertext and releases its lease, then publishes a private ReturnedCredit into a preallocated capacity-one receipt cell. The receipt may carry the separately constructed PeerAccepted marker. Code outside the verifier cannot fabricate acceptance; code outside Packet Drop cannot fabricate return. No client holds an owning packet, so forgetting a consumer or Id cannot bypass drainage on the next explicit tick/cleanup or authority close. This checkpoint adds no autonomous timer. A normal consumer returns bounded metadata only after this ownership path completes. A test hook may delay receipt processing to exercise late acknowledgment; it does not become a caller-supplied boolean or public acknowledgment API.

Lock order is session access/epoch, then mailbox. Mailbox snapshots release their mutex before acquiring access. Receipt publication is nonblocking and never calls the authority, Registry or epoch lock. Receipt drains release their internal synchronization before touching mailbox/Registry state. No queue/status/mailbox/epoch lock spans worker join. Budget reservation completes before taking access/mailbox locks; reservation destruction may release counters during packet drop, but no reservation operation retains a counter lock while acquiring mailbox/access. Explicit terminal cleanup remains synchronous and owns all joins.

Consume runs under exclusive mutable authority access, so applied remove/replace cannot race its verification; existing access guards also exclude concurrent revocation during acceptance. The stored injected time base is shared with start/poll/tick, not an arbitrary caller timestamp. A receipt arriving after expiry, cancellation, close, supersession or slot reuse cannot restore Completed, unlock another claim's fence or close its successor. Exact old grants are released only once. Current poll-cadence-dependent result selection remains documented; this checkpoint does not claim completion-time stamping is fixed.

Before seal, cancellation returns unused output grants without fabricating a packet-drop receipt. After MaySend, any seal/transfer/verification/tick failure, cancellation, expiry or unread discard closes the exact Registry carrier and physically closes its registered mailbox, draining tracked and ordinary packets. Preserve an existing Removed/Replaced/IdleTimeout reason. Close reconciliation runs on direct close/removal/replacement, maintenance failures, discard and all terminal paths, without depending on advisory events or another command. Post-seal transfer failure cannot leave a queued frame available to a later sender. Siblings are cancelled without fabricated responses or automatic replay. Other registrations and successor generations remain intact.

Returned/Completed requires actual join, valid PeerAccepted evidence and the actual packet-drop receipt. Two-slot admission remains charged through output cleanup; early observation disposal cannot free capacity. Cleanup failure/poison or uncertain execution preserves sticky Abort and typed writer ownership. Clean/Retired receipts remain impossible until workers, mailboxes, grants and receipts are drained. No force-close, clean retry or detached cleanup task is added.

## 4. Required isolated tests and implementation boundary

1. Needed-minus-one/exact registration and claim budgets at connection, shared-device and global levels; Registry/mailbox zero-slot, F-minus-one/F-byte limits and occupied-queue refusal before spawn. After Begin, fill all unreserved capacity and verify prepaid 200/502/504 delivery. Exercise each competing producer: no seal/invocation/export, no carrier close on Busy, no stolen reservation.
2. Actual synthetic-peer acceptance and consecutive channel counters; raw receive/inspection never marks Delivered. Unread/forgotten consumer, skipped verification, bad peer, unwind before/after verification, cancellation and deadline equality return actual packet credit and close exactly the affected mailbox/carrier. Another carrier and a reused numeric carrier id remain usable.
3. Inject seal failure after MaySend, successful seal followed by transfer failure, and tick/clock failure while queued. Assert physical drainage, no queued late response, retained execution/status evidence, no replay and no new reservation after Begin. Delay receipt processing through expiry/removal/re-pair/discard and verify no successor effect or early slot reuse.
4. Shutdown/Drop with worker plus queued packet, poisoned cleanup and typed close failure: all real joins, packet receipts and exact grant releases precede Clean, and fault cases retain writer ownership. Keep the scoped Claim suite and all seven Node checks independent. These fixtures do not establish real transport cancellation, batching, production routing or phone interoperability.

Implement as separately tested commits for reservation/fence ownership, then tracked packet/verifier/physical closure composition, with independent review before checkpoint 3. No owner queue, scheduler or public client adoption follows from agreement here. The target-registration allowance, per-claim formula and direct authority consume API above are the concrete refinements proposed for agreement.
