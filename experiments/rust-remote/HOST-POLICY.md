# Synthetic host proof and service policy checkpoint

This checkpoint implements host-proof codecs/host-ID derivation, a temporary-record authority, and the remaining acceptance/memory guards from `rust-owner-remote-recheck-review.md`. It opens no listener or network connection, reads no existing identity/profile/device file, takes no daemon lock, and changes no mobile code or runtime fingerprint.

Rust Ed25519 signing/verification now uses pinned `ed25519-dalek` 3.0.0, with actual Node signatures verified by Rust and independently Rust-signed proofs accepted by the Node room. A consuming challenge verifier adds deadline/generation checks. See [HOST-PROOF.md](HOST-PROOF.md) for primary sources, API details and the explicit weak-key admission difference. Public dependency/docs access was permitted; live endpoints and keys remain excluded.

## Host proof coverage and primary sources

`host_proof::{Challenge, UnverifiedProof, host_id}` supplies bounded object schemas, canonical unpadded base64url, exact 32/64-byte lengths, host-ID binding and field-order-preserving emission. Unknown/duplicate fields, positional arrays, noncanonical base64 and oversized messages are rejected. These are stricter than Node's coercion/extension handling. The 4096-byte cap is also stricter than Node's text UTF-16 cap. No message is marked authenticated by parsing it. Explicit library verification and consuming challenge checks are separate steps.

The already locked RustCrypto `sha2` 0.10.9 is now a normal dependency. Its installed primary source `src/lib.rs` documents `Sha512::digest`; `.cargo_vcs_info.json` identifies RustCrypto/hashes commit `82c36a428f8d6f05f3bfccdedb243e9d1f85359d`, path `sha2`. The source and Cargo checksum were available locally; no current-maintenance or online verification claim is made. Reference: https://github.com/RustCrypto/hashes/tree/82c36a428f8d6f05f3bfccdedb243e9d1f85359d/sha2 . No new hash or signature construction is implemented.

`tests/host-proof-node.mjs` pins TweetNaCl 1.0.3, extracts the exact daemon proof statement and imports the actual relay `createRoom` with in-memory sockets. It records four synthetic seeds, challenges, keys, host IDs, signatures and source hashes. Node rejects wrong challenges, corrupted signatures and wrong host IDs. The Rust example verifies those Node signatures and independently signs the challenges with the Rust library; Node accepts the resulting signatures through its room code. No relay connection is opened. See HOST-PROOF.md.

## Authority API and transaction boundary

`policy::TemporaryAuthority::create_synthetic(host, token, desktop_access, limits, rng)` creates a **new** `milagre-remote-synthetic-*` directory under the OS temporary directory. The constructor accepts no existing path. The directory is 0700 and newly created files 0600 on Unix. A `RUST_REMOTE_SYNTHETIC_ONLY` marker identifies the capability. Only synthetic public device keys/kinds/removal timestamps are written; tokens and private keys stay in memory. Use synthetic inputs only.

- `open_pairing(now_ms)` is a trusted owner action. It opens a multi-device window and invalidates old new-device tickets. It leaves the long-lived wire token unchanged. Multiple new devices may commit during the same window; each opaque ticket is consumed once and each new desktop requires its own approval.
- `begin(source, hello, now_ms, rng)` applies failure quotas and separate known/enrollment work budgets before crypto, derives known/pairable observations from its own records, checks stored kind and desktop support, and returns an opaque instance-bound `Ticket`. It exposes no ACCEPT/channel. `pending_device(&ticket)` returns immutable metadata for a future owner prompt.
- `approve_desktop(&ticket, now_ms)` is a trusted owner event, never a peer message. `cancel(ticket)`, replacement, expiry, removal and retirement invalidate tickets. `expire` must run while idle. No UI authentication or network event routing is supplied.
- `complete(ticket, clock)` takes a monotonic clock closure, commits a new record and derives `ServiceDecision` internally. It reads the clock again in the final generation guard after persistence, and checks ticket instance, authoritative record/kind, pairing generation/deadline and retirement immediately before releasing `Session`. No caller supplies `persisted` or `known` booleans. Known-device metadata refresh is omitted.
- `remove(&mut registry, key, now_ms)` advances shared session revocation, closes matching registry entries, invalidates tickets and persists a tombstone. Same-timestamp removal/reopen remains denied because Node uses strict `<`. `retire()` and authority drop invalidate every issued Session. Fresh post-removal enrollment gets the new epoch; old completed sessions stay refused. See REGISTRY.md.

Writes use create-new transaction files, write/sync, rename to `records.json`, then directory sync. In-memory state advances only after a successful new-device commit. An IO failure retires the authority, including an ambiguous post-rename failure. Removal invalidates memory first and retires on failed persistence. A final deadline failure after a successful commit refuses the channel but leaves the record committed; known reconnect can proceed. The consumed ticket cannot release a second channel; other new devices remain eligible until the window deadline.

Drop removes only the known marker/snapshot and empty directory, never recursively deletes arbitrary files. Tests force a write failure only inside their own temporary capability and restore the deliberately changed directory. There is no existing-store loader, restart recovery, durable identity retirement, production profile migration, or shared daemon writer. The private directory/type checks do not claim confinement against another malicious process with the same UID. A future persistence service needs a separately reviewed ownership/recovery contract.

## Bounds and final acceptance guards

Default policy limits: 64 total active/tombstone records, 16 pending tickets and four pending desktops. `Limits::admission` defaults to 64 remembered direct source IDs, eight failed enrollments per direct source and 32 globally per fixed 60-second window. Known candidates bypass these failure quotas but still require full authentication and authoritative policy. Independent crypto budgets default to 64 known and 16 enrollment work units per second. See [ADMISSION.md](ADMISSION.md) for byte charging, source churn bounds, local status, short saturation and exact compatibility limits.

Established sessions are capped at 16 per authority and four per device. Admission checks precede record commit. `Session` retains its permit and private `Authorized`; borrow `reply()`/`device()` and use checked `seal_encoded`/`open_encoded`; raw Channel extraction is no longer exposed. Drop releases admission. The in-memory registry now owns Session for a synthetic connection. There is no real listener.

One authority owns a 256 MiB global reservation pool. Every device shares a 64 MiB pool across its sessions, retained even across removal/re-pair while the authority lives. Each session has one 64 MiB connection handle; `reader(direction)` and `writer(direction)` use that same handle across both directions. `budget()` supplies that handle for carrier/decrypt/phone buffers. `GlobalBudget::device` and `DeviceBudget::connection` also expose the hierarchy independently. Failed reservations roll back all lower counters, and leases survive handoffs until drop. **Allocations outside frame readers/writers remain the integrator's responsibility**; the policy model is not a whole-service/RSS memory meter. Pending handshake input and pre-auth transport buffers are bounded locally, not charged to session pools. Multiple independently created authorities are isolated synthetic services, not one shared production global pool.

Low-level `Accepted::authorize(decision, still_current)` is a breaking API update. It evaluates the authoritative generation callback after policy validation, then refuses if the acceptance is at least ten monotonic minutes old. Tests cannot bypass the last guard through a stale decision. Caller code can still lie in an attestation/callback; use the authority's state-derived path. Age is checked on authorization, not by a background timer; dropping expired pending values remains the service's duty.

`Channel::open` now runs bounded raw validation before building a `Value`. The allocation test covers dense authenticated plaintext, and authenticated rejection still consumes the receive counter. `open_encoded` remains unchanged and preserves opaque phone bytes, including lone-surrogate JSON escapes and real PUA. Frame and convenience decoder depth/token admission remains 64/65,536. A 16 MiB byte limit does **not** mean dense 16 MiB Node states are accepted. Real-frame token census (paged Chat results and Project state) and owner paging are required before wiring. No real frame/profile census was attempted here.
