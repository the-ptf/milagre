# Fixed-response Claim supervisor integration contract

Status: proposed private synthetic integration, awaiting agreement before API implementation. This is the next implementable slice of [HTTP-CLAIM-PROPOSAL.md](HTTP-CLAIM-PROPOSAL.md), not a second HTTP proposal. It connects only the existing fixed 200/502/504 outcomes to the retained persistent supervisor. It adds no HTTP dependency, URL, arbitrary executor closure, live endpoint, imported profile, mobile change or production admission.

The source-only `rust-owner-summaries-remote-carrier-loss-review.md` closes the preceding carrier-loss P2 for the covered scope and reports no P1/P2. Its explicit-delivery and transfer-failure P3s are prerequisites below, not assumed solved. The existing 256 tests, eight doctests and seven Node checks remain baseline evidence; this document adds no implementation or interoperability evidence.

The earlier persistent-supervisor and HTTP documents remain authoritative on fresh-only storage, typed writer ownership, deadlines and no replay. This document specifies the fixed-response integration between them. The current public `start`, ordinary `MemoryHttp`, scoped `with_claim`, and uninspected legacy work retain their behavior. ## Retained ownership and proposed internal API

Add an optional private `FixedDispatch` to **PersistentAuthority**, not a caller-owned Claim or an executor local to the actor's stack. It contains two executor slots, their actual JoinHandles, completion/cancellation signals, reservations and exact Registry permits. Workers receive only fixed outcome values and a bounded signal/result slot; they hold no authority, store, Registry, mutable channel or caller callback. There is no self-referential authority borrow, unsafe lifetime extension, exported JoinHandle or consumable executor owner. Forgetting a client attempt/receipt cannot detach execution or make authority close eligible.

A crate-private fixture constructor prepares status backing, admission queues and completion storage before writer acquisition where possible. Invalid static limits remain a read-only corrected-retry rejection. Any allocation/spawn failure after Running retains dirty authority/writer ownership under the existing startup contract. Enabling dispatch does not rewrite the store format or persist attempts.

The proposed names describe responsibilities, not a public API commitment:

| Operation                                                                            | Result and ownership                                                                                                                                                                                                                                                            |
| ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `FixedOwner::prepare(token) -> Result<PrepareReceipt, PrepareRefusal>`               | Nonblocking bounded preparation command. The actor validates the actual work/device binding, reserves a status slot, and replies with one non-Clone `FixedAttempt`. No worker or invocation yet. Dropping an unreceived reply drops that attempt and marks its slot releasable. |
| `FixedOwner::submit(attempt, FixedOutcome) -> Result<FixedReceipt, SubmitRejection>` | Successful enqueue consumes the attempt. Before-enqueue Full returns the exact original attempt; stale/expired/stopped refusal is terminal. The observation id is known before submission. Dropping an accepted receipt never cancels or replays.                               |
| `observe(id)`, `cancel(id)`, `ack_terminal(id)`                                      | Bounded shared status access, independent of ordinary command/event capacity. Cancel sets the exact slot's prepaid latch and wakes the actor. Ack hides terminal observation but cannot release executor/output resources or reuse a still-live generation.                     |
| `authority.poll_fixed(now, wake)`                                                    | Short serialized validation, scheduling, finished-thread collection and output steps. It never waits for an unfinished fixture. No arbitrary callback runs under an authority or status lock.                                                                                   |
| `authority.stop_fixed()` / retained cleanup                                          | Disable admission, set all cancellation latches and close owned output. Actual terminal join/drain happens before any authority quiescence proof or consuming terminal write. No public boolean can certify completion.                                                         |

`FixedAttempt` carries an opaque checked status-slot generation plus the original work binding. Acknowledged, absent or previous-boot ids are Forgotten/Unknown, never NotStarted. Cancellation and status access check both service scope and slot generation; a late old receipt cannot affect a reused slot. Device identities come from authoritative session bindings, not caller strings or assertions. Metadata contains no request body or credential. Attempts/receipts retain only scope and generation identifiers, not executor owners or per-slot leases. The shared run-owned table is removable at stop; retained clients see Stopped/Forgotten and cannot keep that table, packets or writer alive.

Use 512 status slots globally and 32 per device, including prepared, submitted, active and retained terminal records. Keep a slot occupied after early acknowledgment until actual executor and output cleanup complete. Preallocate a fixed 16-entry prepare queue and a separate 16-entry submission queue; admit at most one queued submission per device, in addition to its possible active claim. The fixture accepts at most 16 current carriers/device scheduling buckets; reject larger fixture configurations before acquiring the writer. Status accounting for device churn scans the fixed 512 slots rather than growing an unbounded device map. Queue Full is local, never EventOverflow or profile quarantine. Abandoned unsubmitted attempts are reclaimed from their cancellation state on a tick; a deliberately forgotten attempt can occupy its bounded slot until stop, but cannot own a worker. Cancellation before Registry claim records NotClaimed(CancelledBeforeClaim), changes only that attempt, and cannot cancel another attempt's winning work. Once a Registry permit exists, cancellation terminalizes that claimed work even if Begin has not run. Accepted submission that definitively cannot claim records NotClaimed with zero invocations. Only that explicit outcome permits a fresh attempt while the original work remains eligible; there is no automatic retry.

## Claim, Begin and cancellation ordering

Ready inspection arms assembly plus 20,000 ms expiry. The scheduler validates current session/epoch/work serial and reserves the entire fixed execution/output path before marking the Registry job claimed. Claim records one clock sample and checked +340,000 ms / +345,000 ms deadlines. Overflow, budget or spawn refusal produces zero invocations. A successfully spawned gated worker is installed in the authority's retained slot before Begin; every intermediate failure joins it before releasing ownership.

Begin revalidates authority state, carrier, cancellation and deadline. The transition shares synchronization with the cancel latch: if cancellation wins, NotStarted and zero invocations; if Begin wins, MayHaveRun is recorded before the fixture gate opens. Begin occurs in the same actor turn as claim, after resource installation; it is not another externally queued command. No cancellation after Begin can restore NotStarted. Test-only barriers may pause before/after that transition, without becoming a production executor API.

Applied removal, replacement, disconnect, retirement, idle/fragment expiry or stop cancels matching retained slots as well as Registry work. Durable removal invalidates access before its write as today. Before every Begin, result adoption and output handoff, recheck the actual current binding and deadline. Never acquire an epoch/mailbox lock while holding the shared status lock: validate under the epoch guard, then take the bounded status/signal lock to commit. Cancellation uses status/signal only; packet-return notification is nonblocking. Lock-order and poison regressions are required. A stale result can release only its own retained resources. It cannot deliver, close a newer handle, republish Ready or reconstruct an attempt. A refused RemoveDevice command has not applied revocation; this integration does not relabel queue refusal as success.

Tick equality expires. At the 340,000 ms deadline, request cancellation; stage 504 only after the actual worker has exited and joined, while the connection and 345,000 ms completion margin remain valid. A worker still exiting consumes that margin; it does not extend the deadline. At completion expiry, cancel/drain and retain TimedOut with execution evidence. If any frame was sealed without confirmed fixture delivery, retain Unknown and close the exact carrier. Existing earlier idle expiry still wins. Ready expiry retains the current no-response difference; prepaid Node 429, upload 400/413 parity and actual phone retry behavior remain later gates.

## Finished-thread supervision and actor turns

Each executor has a preallocated result slot and coalesced wake state; completion never uses Approval/Closed event capacity. A completion flag is not a join. During normal service, inspect the two retained JoinHandles with `is_finished()` and consume `join()` only for a finished thread. Retain execution credit until join returns, including panic. No blocking `collect` on an unfinished executor, detached reaper or unbounded completion thread is introduced. This is non-waiting supervision of unfinished work, not a hard real-time promise about OS join latency, mutex scheduling or synchronous authority fsync.

Workers publish the result before returning, but that wake can precede thread exit. A still-unfinished handle remains in the table and is checked on the next bounded tick even if no further wake arrives. Panic likewise becomes visible through the finished handle; it retains MayHaveRun conservatively and sets sticky service Abort, matching the current scoped panic policy. Poison is cleanup-only, never a reason to resume dispatch.

Every actor turn services stop/cancellation and due deadlines first, scans the two executor slots, reconciles closed handles/mailboxes, and performs bounded output/completion work. It then processes at most one existing control, one existing ordinary command, one preparation and one submission/scheduling step before repeating. Queue mutexes are released before authority operations, encryption, fsync or join. The wait predicate includes claim wake/cancel/output state, not only existing command queues. A checked wake-generation counter is sampled before each scan and included in the wait predicate; a concurrent completion or packet return cannot be erased by clearing a readiness flag after its notification. Counter exhaustion aborts without wrapping. Periodic ticks remain 1..100 ms, so manual-clock expiry and completed output progress without owner polling or incoming commands. Completion, inspection expiry and end-claim promotion reassert the existing coalesced WorkAvailable signal; refused drains cannot clear it.

## Fairness and prepaid capacity

Use round-robin selection over at most 16 active device buckets, then carrier generations within each device. One claim globally per device may retain execution/output cleanup; two slots globally may be occupied. Charge these slots through join and final output credit return, not just result production, so unread output cannot create unlimited replacement workers. Each scheduler visit inspects at most one submission per device. A blocked device cannot monopolize scans or queue positions; a newly admitted device joins behind the cursor. IDs and array indexes are checked, with no eviction of unacknowledged evidence.

At saturation, the two running or output-held claims can still delay everyone until completion/cancellation/deadline; the contract does not promise preemption or equal wall-clock latency. With an eligible queued device and a free slot, one bounded round visits it even if another device continuously submits. A continuous control stream cannot suppress the fixed-claim maintenance/round, although the separate problem of admitting RemoveDevice into a DrainWork-filled control lane remains open. General data-ingress and Disconnect fairness are not claimed solved.

Reserve serialized/parsed status backing and ring capacities before allocation using checked `size_of`/capacity calculations and documented allocator/container allowances. Reserve each occupied status record from the authoritative device/connection/global budget, including observation retention; reserve shared backing once from the same global pool. Do not invent a second independent device budget. Fail locally before invocation on any shortage. Status completion writes into prepaid storage, not an allocation-backed event. `events: 1` stays supported and approvals keep their existing local-refusal policy.

Keep the existing fixed-worker allowance: 2 MiB stack, 64 KiB output/scratch, 4 KiB execution bookkeeping, 2 KiB retained per-claim metadata, plus separately accounted new table/mailbox receipts. Actual new capacity calculations must be pinned by tests rather than hidden in those old allowances. One response is at most 1,024 encrypted bytes. Existing 64 MiB connection/device and 256 MiB global limits remain; the full-HTTP 128 MiB/64 MiB-body configuration is not adopted here.

Before Begin, reserve one Registry output slot and one tracked mailbox slot, with checked byte allowances covering the maximum frame and packet metadata, as well as its final lease. All ordinary producers must count these reserved slots/bytes against their available capacity. No fresh global or mailbox credit is acquired after invocation. Transfer moves the existing lease; it does not double-charge frame bytes. For the first implementation, a claimed carrier has an exclusive egress fence until its tracked frame is consumed or closed: other Send/Finish/MemoryHttp operations on that carrier refuse before sealing/invocation. Incoming requests, keepalives, cancellation and other carriers still progress. Admission requires its earlier Registry and mailbox output to have drained. This explicit fixture restriction avoids counters overtaking a reserved but not yet queued frame.

## Explicit fixture delivery and packet destruction

Do not adapt the current `bytes()`-then-normal-Drop convention into asynchronous transport. Add a private tracked packet variant and internal delivery outcome. Bare drop, skipped read, error, unwind or unknown handoff after sealing means loss and exact-carrier closure. A successful `bytes()` call alone never mints Delivered. Delivery evidence and credit-return evidence are different records.

For this synthetic checkpoint, only a private `consume_fixed(&mut phone_channel)` operation may mark fixture delivery: it checks the existing access guard and deadline, opens the full frame using the actual synthetic peer Channel, records acceptance, then destroys the ciphertext packet and lease. It returns bounded fixed-response metadata for assertions, not an owned packet, executor or mutable status record. A failed open records loss. Its receipt is private, generation-bound and written into prepaid storage; callers supply neither a success boolean nor a cleanup boolean. Ordinary `MemoryCarrier::receive()` must refuse a tracked front packet without popping or skipping it. This prevents a public Vec export from bypassing accounting. Existing untracked MemoryCarrier behavior remains unchanged.

The authority retains the close capability and accounting reference for every tracked mailbox, so forgetting a client cannot strand its packet outside service ownership. Packet Drop alone mints ReturnedCredit after ciphertext and lease destruction. Queuing the packet is MaySend/queued, not Completed. Successful peer acceptance plus actual packet credit return permits fixture Returned/Completed. A client that never consumes causes deadline closure. `ack_terminal` cannot release the mailbox reservation early. The actor reconciles Registry closure into `MemoryCarrier::close` before publishing terminal cleanup; dropping advisory Closed events cannot suppress physical close or packet receipts.

On loss, remove the exact claimed job with its retained terminal status, close the current carrier without promoting siblings, and drain all its queued output. Preserve an existing Removed/Replaced/IdleTimeout reason. Other carriers and successor generations remain intact. Siblings receive no fabricated response and never replay automatically. This tests synthetic peer acceptance, not socket write or phone acknowledgment; the real transport delivery contract remains excluded.

## Shutdown and failure ownership

Out-of-band Requested/Abort disables prepare, submit and Begin under the same admission synchronization. Abort remains dominant. Revoke all access, cancel approvals/queued attempts and executor gates, and close tracked/untracked mailboxes. An unqueued rejected command returns NotExecuted only after releasing its ingress lease. Accepted claim receipts remain observations; stopped or lost receipts never authorize replay.

Normal turns continue bounded cleanup until all fixed workers have finished and been joined, every packet has an actual return receipt, and all queue/status reservations owned by the run are drained. Terminal shutdown may wait for remaining workers; it must not detach or force Clean. Authority's own close/Drop must also cancel and join its retained executors, so a forgotten client or unexpected actor unwind cannot bypass this order. Owner-side recovery joins the service worker, recovers the retained Runtime, and drains any remaining authority-owned workers/mailboxes before extracting the writer. No queue/status/epoch lock is held across a potentially waiting join.

Only after child-worker cleanup, authority quiescence, mailbox/queue drainage and the service thread's actual join may the joining owner call terminal persistence and return Clean/Retired. Typed faults keep the exact broker/writer guards via existing StoppedService/CloseFailure. Worker panic, poisoned retained state, clock fault or ambiguous write makes Abort sticky and forbids Clean. Synchronous fsync may delay shutdown; unexpected unwind inside consuming terminal persistence retains the existing documented limitation. No recovery, clean retry, force path or persisted request replay is added.

## Implementable checkpoints and acceptance gates

1. **Retained executor core, next implementation.** Add private authority-owned two-slot fixed dispatch storage, gated spawn/install/Begin, cancellation latches, finished-handle polling, checked deadlines and shutdown drainage. Keep it accessible only to internal tests. No owner commands or automatic scheduling yet. Test before/after-Begin cancellation, forgotten receipt, actual finished-thread panic accounting, delayed exit while another carrier remains usable, poisoned retained recovery, exact budgets and Clean refusal until all joins. Retain scoped Claim tests as an independent baseline.
2. **Tracked output capability.** Add prepaid Registry/mailbox count and byte reservations, exclusive carrier egress fence, explicit synthetic peer acceptance and actual packet-drop receipt. Test full queues/global pressure after Begin; failed transfer after seal; tick/clock failure during MaySend; seal failure after the barrier; unread/forgotten/error/unwind output; exact-generation physical close; consecutive counters; another carrier; and acknowledgment before cleanup. Independent review before wiring clients.
3. **Private owner queue and fair actor pump.** Wire consuming prepare/submit/status/cancel to the retained core, round-robin device/carrier scheduling and independent completion/tick wakes. Deterministic barriers prove Full returns the original attempt, duplicate work invokes once, accepted receipt loss does not replay, cancellation ignores command/event saturation, completed output wakes without commands, 504 fits the margin with ordinary keepalive, Ready expiry promotes/readies once, stale callbacks cannot affect re-pair, and saturated shutdown drains before Clean. Test status/source churn bounds, 16-carrier readiness, one-slot approval coexistence and the bounded-round fairness guarantee.

Each checkpoint is synthetic-only, separately committed and reviewed. Preserve the existing Rust/doctest/Node reciprocal suite and strict all-target Clippy. Compile-fail or visibility tests must prevent carrier-client escalation and owning-worker/packet escape; runtime tests alone do not prove those type boundaries. No network adapter begins as part of these checkpoints.

Still separate: reserved revocation versus duplicate DrainWork admission, Disconnect saturation, complete ingress fairness, async persistence/fsync scheduling, full response-body allocator accounting, Node 429/400/413 parity, dense-state/Unicode path-header compatibility, batching, actual HTTP transport cancellation and buffer limits, production routing/admission/credentials, broker-loss recovery and live phone interoperability. Agreement on this document does not authorize any of them.

## Concluded checkpoint 1 scope

The parent accepted checkpoint 1 on this contract: a private authority-owned two-slot retained executor core, exact Registry permits, bounded fixed results, gated installation before atomic Begin, cancellation/deadlines, finished-handle polling followed by actual join, execution credit through join, sticky Abort/poison cleanup, and terminal close/Drop drainage without a lock across join. There is no owner queue, automatic scheduler, mailbox output or new client API in this checkpoint. Fixed results stay in memory and cannot be delivered. Explicit tracked delivery and prepaid output remain mandatory before asynchronous egress; `bytes()` alone cannot mean delivered.

The required tests include removal/carrier replacement/close cancellation, failure after spawning and installing a worker, panic before and after Begin, forgotten observers, progress on another carrier, bounded memory and retained terminal guards. A non-owning observer cannot retain a worker, and no completion flag stands in for JoinHandle consumption. No unresolved contract question blocks this private core. The later tracked-output and owner-pump checkpoints remain separately reviewed work.
