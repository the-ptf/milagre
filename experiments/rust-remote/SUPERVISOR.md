# Synthetic remote supervisor

`supervisor::Supervisor::spawn_synthetic(identity, limits, clock)` owns one `TemporaryAuthority`, one `Registry`, and one joined standard-library worker thread. It creates a new marked temporary record directory only. There is no existing-store/path constructor, listener, socket, mobile change, daemon lock or production identity import. All inputs in the tests are synthetic.

The removal-epoch and admission safety commits precede this checkpoint. See [REGISTRY.md](REGISTRY.md) and [ADMISSION.md](ADMISSION.md). The supervisor uses those state-derived decisions, shared revocation epochs and admission budgets; it never supplies caller assertions that a device is known, approved or persisted.

## Ownership and events

`Supervisor::client()` returns a cloneable **trusted service/owner capability**. It is not a capability to hand to a remote peer: its command enum includes pairing, approval, removal, retirement and synthetic identity replacement. A future transport adapter must have a narrower authenticated routing interface. No owner UI authentication is implemented here.

1. `Attach { id, carrier: MemoryCarrier }` consumes a one-use in-memory carrier binding and returns an opaque registry `Handle`. Reusing the carrier id replaces its old generation. The old mailbox closes, its approval ticket is cancelled, and old work tokens cannot send to its successor. The same `MemoryCarrier` object cannot be attached twice.
2. `Hello { handle, source, bytes }` invokes the authority with the exact wire bytes and explicit relay/direct source. A new desktop produces `Event::Approval { permit, device_key }`; its actual authority `Ticket` stays inside the worker. `Approve(permit)` consumes the exact owner capability. Other accepted devices complete through authoritative records and persistence before ACCEPT. An authenticated pending approval uses its pairing-window deadline, is bounded by authority pending-desktop limits, and is protected from unauthenticated OPEN eviction.
3. `Request { handle, bytes }` sends encrypted synthetic phone request frames through the registry's bounded assembler and scheduler. `Event::Work(WorkToken)` exposes only an opaque continuation/cancellation token. `Finish { token, response }` accepts a trusted serialized fake-bridge response; generation, epoch, deadline and running-state checks precede sealing. Queued work is promoted by completion or timeout. There is no actual HTTP worker or request-body export in this checkpoint.
4. `RemoveDevice(key)` calls the composed authority removal: shared epoch revocation and registry closure precede the temporary record write. A write failure retires all remaining authority/registry access. `Retire` closes pending and active carriers and clears approvals/work. `Replace(SyntheticIdentity)` first retires all old state, then creates a fresh disposable authority/registry; failure leaves the old identity retired. It preserves the service's single global memory pool. Old handles, approvals and completions never match the replacement.
5. `Disconnect(handle)` closes that generation. `Send { handle, encoded }` is a trusted synthetic output hook preserving raw JSON bytes. `Event::Closed(handle)` is advisory; the handle's atomic status and work token status remain authoritative if notification delivery is unavailable. No wire cancellation message was added.

## Automatic deadlines and shutdown

The worker runs authority expiry and registry `tick` before every command, again after waiting, and periodically while idle. `tick_ms` defaults to 10 ms and is constrained to 1..100 ms. `Clock::monotonic()` advances with `Instant`; `Clock::Manual(ManualClock)` is an injected test clock. Advancing the manual clock does not call or wake a tick. Tests wait for automatic close/work events, including a real-clock HELLO timeout, without issuing polling commands.

All changes and fake carrier delivery are serialized in this worker. The mailbox consumer also checks the unforgeable session epoch before taking a packet; revocation waits for an already-started guarded delivery and prevents subsequent delivery. Lock acquisition clones the epoch guard outside the mailbox lock to preserve the guard-before-mailbox order. Previously consumed caller-owned bytes cannot be recalled.

`shutdown(self)` and `Drop` signal stop out of band, wake the worker and join it. A full command/event queue cannot prevent stop. Queued unexecuted commands receive `NotExecuted`; queued Attach carriers close even if their receipt was dropped. The worker retires authority/registry state, cancels queued and running work tokens, clears output and event queues, drops every owned lease, and removes the temporary authority directory. `is_finished` is set after actor disposal. Cloned `Client` handles may remain for diagnostics but cannot submit further work. No worker thread or background task is detached, and no per-request task is spawned.

This is cooperative shutdown, not an OS-level hard deadline. A currently running bounded crypto operation or synchronous temporary-file write/fsync finishes before join returns; an unresponsive filesystem can delay shutdown. There is no unbounded user callback inside the supervisor. External HTTP/process tasks, future socket writers, and their cancellation/join contracts are still absent.

## Bounds and unknown outcomes

All queues are bounded. Commands default to 64 queued entries (maximum 256), plus one executing command, under a shared 32 MiB retained-byte budget (maximum 64 MiB). Admission charges owned Vec/String **capacity**, plus a 1 KiB per-command allowance, before the supervisor takes the queued entry; oversized inputs are rejected before enqueue. The caller's allocations before submission remain caller-owned. HELLO, request and output lengths retain their protocol caps. Identity tokens are limited to 1 KiB capacity.

Events default to 128 entries (maximum 1,024), with a 2 KiB reservation per event and no body payloads. Advisory `Closed` events occupy at most half the configured slots (zero for a one-slot queue). Extra closures are dropped and counted in `Client::event_stats().closed_dropped`. Approval/Work events may evict advisory entries and are read first, in their own FIFO order; closure notifications are also FIFO within their class. Advisory entries are released first if an authoritative reservation needs memory. Only inability to queue an authoritative event records `StopReason::EventOverflow` and stops/revokes the service. Future production notification policy may differ. `next_event(timeout)` is a bounded observer wait, not a deadline-driving call.

Each carrier mailbox defaults to 256 frames and 32 MiB, capped at 256 frames/64 MiB. Its copies use the exact Session connection/device/global budget, so queued registry bytes and delivered-but-unconsumed copies are charged simultaneously. Command/event pools share the same 256 MiB service global budget as all sessions, including across identity replacement. `Client::retained_bytes` exposes that accounting. Constructor metadata, bounded temporary cryptographic/parser allocations and arbitrary copies retained by a test consumer are not a whole-process RSS claim. `MemoryCarrier::receive` moves one packet to the consumer and releases its service lease; close drops all unconsumed packets.

`submit` returning `Full` means the command was not admitted; `NotExecuted` means shutdown prevented execution. A returned `Receipt` observes one accepted command. Dropping a receipt does **not** cancel or replay that mutation. A receipt timeout, worker failure, or stop during execution returns `UnknownOutcome`: retain the receipt after a timeout if another observation is needed, and never resubmit to infer success. A successful command receipt means its service transition ran, not that a phone acknowledged delivery.

Fake carrier delivery is attempted once. `inject_unknown_delivery` simulates an acknowledgement lost after a possible send. Delivery failure closes the carrier, clears remaining output and returns `DeliveryUnknown` to the command receipt; neither the supervisor nor registry retries it or transfers it to a new generation. Work completion and phone delivery are separate states. The tests assert the attempt count remains unchanged after a stale retry.

## Evidence and remaining services

This checkpoint adds 14 integration tests and three deterministic queue/shutdown unit tests, bringing the crate to **106 tests and four compile-fail doctests**. Coverage includes automatic HELLO/idle/approval/request deadlines, promotion while idle, source-independent approval protection, composed removal/re-pairing, failed removal persistence, retirement/replacement, old callback refusal, queue byte/count saturation, event overflow, unknown delivery, dropped receipts, full-queue shutdown, cleanup and lease release. Existing five Node checks remain unchanged: crypto/frame reciprocity, phone codec/mobile dispatch reciprocity, Ed25519 proof reciprocity, lifecycle trace and pairing-window trace. These are synthetic transport/service checks, not actual phone interoperability.

Still missing: production identity/device persistence and restart recovery; owner-authenticated command/UI routing; peer RPC/event dispatch and an HTTP forwarding worker with response status/error mapping; external task cancellation; live request/subscription services; LAN discovery, relay proof/reconnect/hibernation lifecycle, socket ingress/backpressure/fairness and relay edge admission; real-frame token census and actual phone interoperability. A malformed/oversized request still closes its carrier rather than returning Node's per-request 400/413/429. No claims of production readiness, real network verification or mobile runtime compatibility testing are made.

The advisory saturation safety tests cover 1,000 Attach/evict cycles without an event consumer, an established phone surviving, subsequent Work and Approval delivery, a one-slot event queue, and authoritative eviction of an advisory entry from a full queue. Closure status remains available on retained handles even when its notification is dropped.
