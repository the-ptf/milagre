# Synthetic remote supervisor

`supervisor::Supervisor::spawn_synthetic(identity, limits, clock)` owns one `TemporaryAuthority`, one `Registry`, and one joined standard-library worker thread. It creates a new marked temporary record directory only. There is no existing-store/path constructor, listener, socket, mobile change, daemon lock or production identity import. All inputs in the tests are synthetic.

The removal-epoch and admission safety commits precede this checkpoint. See [REGISTRY.md](REGISTRY.md) and [ADMISSION.md](ADMISSION.md). The supervisor uses those state-derived decisions, shared revocation epochs and admission budgets; it never supplies caller assertions that a device is known, approved or persisted.

## Ownership and events

`Supervisor::owner()` returns a cloneable **trusted service/owner capability**, `OwnerClient`. `client()` and the `Client` type alias remain compatibility names. It is not a capability to hand to a remote peer: its command enum includes pairing, approval, removal, retirement and synthetic identity replacement. `OwnerClient::carrier(handle, source)` now mints a narrower `CarrierClient`, bound to one opaque generation and trusted source. It accepts only `CarrierCommand::{Hello, Request, Disconnect}`; it cannot attach/replace carriers, approve, drain owner work, finish requests, send owner output, remove or replace identity, or read owner events. The trusted owner router alone assigns handles and sources. Compile-fail tests prove owner commands and events are inaccessible. No owner UI authentication is implemented here.

1. `Attach { id, carrier: MemoryCarrier }` consumes a one-use in-memory carrier binding and returns an opaque registry `Handle`. Reusing the carrier id replaces its old generation. The old mailbox closes, its approval ticket is cancelled, and old work tokens cannot send to its successor. The same `MemoryCarrier` object cannot be attached twice.
2. `Hello { handle, source, bytes }` invokes the authority with the exact wire bytes and explicit relay/direct source. A new desktop produces `Event::Approval { permit, device_key }`; its actual authority `Ticket` stays inside the worker. `Approve(permit)` consumes the exact owner capability. Any failure after taking its ticket closes that protected carrier; an early failure also cancels the still-owned authority ticket. Desktop setup rechecks the current clock after crypto, and a failed `wait_approval` cancels its ticket and closes its carrier. Even a clock error during consuming authority completion releases the ticket. Other accepted devices complete through authoritative records and persistence before ACCEPT. An authenticated pending approval uses its pairing-window deadline, is bounded by authority pending-desktop limits, and is protected from unauthenticated OPEN eviction.
3. `Request { handle, bytes }` sends encrypted synthetic phone request frames through the registry's bounded assembler and scheduler. `Event::WorkAvailable` is one coalesced readiness edge, independent of the event queue. `DrainWork { cursor, limit }` returns `Reply::Work(WorkPage)` with at most 64 opaque continuation tokens and a registry-bound next cursor. `Finish { token, response }` accepts a trusted serialized fake-bridge response; generation, epoch, deadline and running-state checks precede sealing. Queued work is promoted by completion or timeout. Draining is non-consuming: lost receipts may be retried without claiming, executing or losing jobs. Tokens remain owned by the registry until completion/cancellation/deadline. Paging orders by carrier generation and request serial; new promotions trigger another readiness edge, so restart from None for each new edge to include work added behind an old cursor. A page can be empty after expiration. Duplicate tokens never authorize duplicate completion. Readiness is not permission to execute an external side effect; that remains a trusted dispatcher responsibility. Owner-only `DispatchSynthetic` now runs the one-shot in-memory HTTP contract described in [HTTP-DISPATCH.md](HTTP-DISPATCH.md). There is no network HTTP worker or request-body export.
4. `RemoveDevice(key)` calls the composed authority removal: shared epoch revocation and registry closure precede the temporary record write. A write failure retires all remaining authority/registry access. `Retire` closes pending and active carriers and clears approvals/work. `Replace(SyntheticIdentity)` first retires all old state, then creates a fresh disposable authority/registry; failure leaves the old identity retired. `Client::is_retired()` exposes identity retirement separately from worker `stop_reason()`/`is_finished()`; a successful explicit replacement clears retirement only after installing both new owners. It preserves the service's single global memory pool. Old handles, approvals and completions never match the replacement.
5. `Disconnect(handle)` closes that generation. `Send { handle, encoded }` is a trusted synthetic output hook preserving raw JSON bytes. `Event::Closed(handle)` is advisory; the handle's atomic status and work token status remain authoritative if notification delivery is unavailable. No wire cancellation message was added.

## Automatic deadlines and shutdown

The worker runs authority expiry and registry `tick` before every command, again after waiting, and periodically while idle. `tick_ms` defaults to 10 ms and is constrained to 1..100 ms. `Clock::monotonic()` advances with `Instant`; `Clock::Manual(ManualClock)` is an injected test clock. Advancing the manual clock does not call or wake a tick. Tests wait for automatic close/work events, including a real-clock HELLO timeout, without issuing polling commands.

All changes and fake carrier delivery are serialized in this worker. The mailbox consumer also checks the unforgeable session epoch before taking a packet; revocation waits for an already-started guarded delivery and prevents subsequent delivery. Lock acquisition clones the epoch guard outside the mailbox lock to preserve the guard-before-mailbox order. Previously consumed caller-owned bytes cannot be recalled.

`shutdown(self)` and `Drop` signal stop out of band, wake the worker and join it. A full command/event queue cannot prevent stop. Queued unexecuted commands receive `NotExecuted`; queued Attach carriers close even if their receipt was dropped. The worker retires authority/registry state, cancels queued and running work tokens, clears output and event queues, drops every owned lease, and removes the temporary authority directory. `is_finished` is set after actor disposal. Cloned `Client` handles may remain for diagnostics but cannot submit further work. No worker thread or background task is detached, and no per-request task is spawned.

This is cooperative shutdown, not an OS-level hard deadline. A currently running bounded crypto operation or synchronous temporary-file write/fsync finishes before join returns; an unresponsive filesystem can delay shutdown. There is no unbounded user callback inside the supervisor. External HTTP/process tasks, future socket writers, and their cancellation/join contracts are still absent.

## Bounds and unknown outcomes

All queues are bounded. Commands default to 64 queued entries (maximum 256), plus one executing command, under a shared 32 MiB retained-byte budget (maximum 64 MiB). Admission charges owned Vec/String **capacity**, plus a 1 KiB per-command allowance, before the supervisor takes the queued entry; oversized inputs are rejected before enqueue. The caller's allocations before submission remain caller-owned. HELLO, request and output lengths retain their protocol caps. Identity tokens are limited to 1 KiB capacity.

Events default to 128 queued entries (maximum 1,024), with a 2 KiB reservation per entry and no body payloads. Work readiness occupies one additional fixed bit, not one queued event per request: the legitimate default 16 carriers × 16 in-flight requests cannot overflow notifications. Only successful initial DrainWork execution clears the bit; observing WorkAvailable or a refused/invalid drain leaves it set; newly promoted work sets it again. A discarded notification or page never removes registry work, and an explicit DrainWork from None always reconstructs the live set. Approval events retain their bounded authoritative queue; advisory Closed events occupy at most half its slots and may be dropped/evicted. `event_stats` reports drops and oldest queued advisory age (real monotonic milliseconds). Queue scans are linear up to 1,024 entries; work scans are bounded by 256 in-flight tokens. Only an unqueueable approval can cause EventOverflow, not work population or closure churn. `next_event` prioritizes approvals, then readiness, then advisories. A repeated readiness observation cannot starve a queued approval.

Each carrier mailbox defaults to 256 frames and 32 MiB, capped at 256 frames/64 MiB. Ciphertext and its exact Session connection/device/global lease now move from the registry into the mailbox; handoff does not allocate a copy or reacquire budget. Delivered-but-unconsumed packets remain charged until consumption or close. Command/event pools share the same 256 MiB service global budget as all sessions, including across identity replacement. `Client::retained_bytes` exposes that accounting. Constructor metadata, bounded temporary cryptographic/parser allocations and arbitrary copies retained by a test consumer are not a whole-process RSS claim. `MemoryCarrier::receive` moves one packet to the consumer and releases its service lease; close drops all unconsumed packets.

`submit` returning `Full` means the command was not admitted; `NotExecuted` means shutdown prevented execution. A returned `Receipt` observes one accepted command. Dropping a receipt does **not** cancel or replay that mutation. A receipt timeout, worker failure, or stop during execution returns `UnknownOutcome`: retain the receipt after a timeout if another observation is needed, and never resubmit to infer success. A successful command receipt means its service transition ran, not that a phone acknowledged delivery.

Fake carrier delivery is attempted once. `inject_unknown_delivery` simulates an acknowledgement lost after a possible send. Delivery failure closes the carrier, clears remaining output and returns `DeliveryUnknown` only to the output-producing command whose exact carrier generation failed; unrelated command results are unchanged, and other failures remain visible through carrier status/advisory closure events; neither the supervisor nor registry retries it or transfers it to a new generation. Work completion and phone delivery are separate states. The tests assert the attempt count remains unchanged after a stale retry.

## Evidence and remaining services

Supervisor coverage now includes 31 integration tests and 12 deterministic unit tests. The crate totals **135 tests and six compile-fail doctests**. Coverage includes automatic HELLO/idle/approval/request deadlines, promotion while idle, source-independent approval protection, composed removal/re-pairing, failed removal persistence, retirement/replacement, old callback refusal, queue byte/count saturation, event overflow, unknown delivery, dropped receipts, full-queue shutdown, cleanup and lease release. Six Node checks cover the new actual-Node HTTP forwarding differential plus the existing checks: crypto/frame reciprocity, phone codec/mobile dispatch reciprocity, Ed25519 proof reciprocity, lifecycle trace and pairing-window trace. These are synthetic transport/service checks, not actual phone interoperability.

Still missing: production identity/device persistence and restart recovery; owner-authenticated command/UI routing; peer RPC/event dispatch and a network HTTP forwarding worker (synthetic status/error mapping now exists); external task cancellation; live request/subscription services; LAN discovery, relay proof/reconnect/hibernation lifecycle, socket ingress/backpressure/fairness and relay edge admission; real-frame token census and actual phone interoperability. A malformed/oversized request still closes its carrier rather than returning Node's per-request 400/413/429. No claims of production readiness, real network verification or mobile runtime compatibility testing are made.

The advisory saturation safety tests cover 1,000 Attach/evict cycles without an event consumer, an established phone surviving, subsequent Work and Approval delivery, a one-slot event queue, and authoritative eviction of an advisory entry from a full queue. Closure status remains available on retained handles even when its notification is dropped.

The lifecycle follow-up tests cover repeated approval failures at record capacity without pinning carrier slots, invalidated approval before completion, expiry between HELLO acceptance and approval setup, completion-clock failure releasing its ticket, unrelated carrier failure during Finish and owner commands, and failed replacement status followed by explicit recovery. No failed output is retried.

Remaining review P3s are separate from these fixes: low-level synchronous delivery callbacks still hold the authority read guard and must stay short/non-reentrant; no real socket writer is wired. Per-key crypto caps do not guarantee a share against a flood using several known keys. The idle worker still uses its configured fixed maximum tick interval. The compatibility `Client` alias remains a full-owner capability; transport code must receive the new bound CarrierClient. There is no asynchronous authorization stage in this single serialized worker; a future asynchronous adapter will need a separately bounded authorizing state. Admission diagnostic categories include overlapping totals and must not be summed as disjoint classes.

Service state is observed as Running (Running stop reason, not retired), Running+Retired (Running stop reason, retired), Stopping (non-Running reason, not yet finished), or Stopped (`is_finished`). Failed Replace leaves Running+Retired until explicit recovery or shutdown. Approval serials use checked addition and never wrap; a forced-exhaustion test verifies ticket cancellation and carrier closure. Request is now included in delivery-target attribution for future immediate same-carrier responses.

## Control admission safety follow-up

Retire, RemoveDevice, Approve and DrainWork use a separate priority FIFO: eight queued controls plus one executing, each at most 2 KiB of charged capacity. A fixed **18 KiB** reservation is acquired from the same service-global pool at construction and released at actor disposal. Carrier traffic and large owner payloads cannot consume those bytes; even a full global pool cannot prevent a bounded revoke from being admitted. Retained-byte diagnostics include this idle reservation. Controls execute before queued data, but do not interrupt an already executing bounded operation. A trusted owner can still fill its own eight slots; stop/shutdown remains out of band.

General commands retain their configured queue and byte caps. Carrier submissions add caps of eight queued commands/2 MiB per opaque handle generation and 32/16 MiB per trusted source. Aggregate carrier occupancy is at most half the configured general command slots/bytes (one slot minimum), leaving general owner capacity. Count/byte scans are bounded by the configured maximum 256 entries; no persistent source map accumulates under churn. These are queue caps plus at most one executing command. Relay is a shared source, not a per-phone IP claim. Compatibility OwnerClient Hello/Request/Disconnect submissions also take these data quotas (Request/Disconnect conservatively use Relay); adapters should use the bound CarrierClient for precise source attribution.

A deterministic test queues 64 attempted requests from one carrier, verifies only eight admit and another carrier's HELLO still admits, exhausts general ingress and all remaining global bytes, then proves both RemoveDevice and Retire admit and revoke before queued traffic. Further tests cover retained capacity, source isolation, readiness after a full control queue refuses DrainWork, invalid drains, and approval priority. This safety checkpoint adds three tests; restart implementation remains paused.

## Receipt publication and ingress release

The disposable worker previously published its result before the envelope's ingress Reservation dropped at scope exit. A caller could observe a completed late Finish while its four-byte `null` response still charged 1,028 bytes, explaining the intermittent 19,460-versus-18,432 retained-byte assertion. This was a completion-ordering race, not leaked request work.

Execution and NotExecuted rejection now share publication that releases the command's ingress lease before sending its result. This does not release another queued command, event, response or mailbox lease. The new test uses admitted-byte observation plus two channel handshakes: it parks the worker after publishing but before envelope scope exit, observes zero ingress, and admits the next command against the same byte limit. It covers success and failure, joins before asserting, and uses no scheduling sleeps or retry loop. Before the fix it deterministically failed with 1,024 bytes still charged; after the fix both cases and the original removal regression pass. The persistent supervisor already releases its execution lease before publication and is unchanged here.
