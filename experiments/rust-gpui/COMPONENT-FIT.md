# gpui-component fit check (WP-01)

Which `gpui-component` 0.9.1 widgets Milagre adopts, wraps or owns, with the evidence: headless tests in
`src/fitcheck/` (they run under `cargo test`), snapshots of the fit-check gallery (`--features fitcheck`), and the
theme bridge in `src/theme/component_bridge.rs`. Written 2026-11-11 against `gpui-pre` 0.3.12, `gpui-component`
0.9.1 and `gpui-base` 0.9.1 (the behaviour layer `gpui-component` is built on). Answers decisions D1 and D8 of
`PORT-MAP.md`.

## Summary

- **Adopt the hard parts.** The rich text view (markdown, window-wide selection, extensions, streaming), the text
  area (atomic tokens, undo, IME, auto-grow) and the diff view pass Milagre's checks with Milagre's own rules
  plugged in through their public hooks. Each is a wrapper, not a fork.
- **Keep what is ours.** The transcript list (GPUI `list`), the sidebar list (`uniform_list`), `ui::Button`,
  `ui::Checkbox`, the range slider, motion and the status pill stay ours: either they already match DESIGN.md
  exactly or gpui-component's version does not fit.
- **Theme through the bridge, size through a wrapper.** The bridge carries every colour, the radii, fonts and the rem
  size. It cannot carry per-widget heights, the 13px label size or DESIGN.md's focus ring: each adopted widget gets
  a thin wrapper in `src/ui/` or `src/text/` that sets them.
- **`gpui_component::Root` must become the window root** (dialogs, popovers, tooltips and the window-wide selection
  need it). It sets the window's rem size from the theme every frame; the bridge keeps that at 16, which is also
  what our `p_*`/`gap_*` spacing assumes.
- **D1:** on `gpui-pre`, a wry webview is a native view on top of everything: GPUI cannot draw over it and cannot
  clip it. Use it only where nothing GPUI overlaps (the Artifact panel body), hide it while a GPUI overlay is open,
  and show HTML replies as cards with a static snapshot.
- **D8:** per widget, as in the table. The rule: adopt behaviour from gpui-component or gpui-base, never its look;
  a widget whose look cannot be set from the theme plus a wrapper is owned.

## Theme bridge

`theme::component_bridge::init` runs after `gpui_component::init` (in `app::init`) and again on every
`cx.set_global::<Theme>(..)`. It installs Milagre Blue's light and dark schemes as gpui-component's two theme
configs, so even `gpui_component::Theme::change(mode)` loads Milagre's colours.

Evidence: `theme::component_bridge::tests` (`dark_tokens_reach_gpui_component`, `light_tokens_reach_gpui_component`,

`fit-controls-dark.png` and `fit-controls-light.png`.

Found while bridging:

- **Rem size.** `Root` calls `window.set_rem_size(theme.font_size)` every frame and every widget height and text step
  is in rems. At the 13px body size heights came out at 26, 19.5, 16 and 14.5 (half pixels); at 16 they are 32, 24,
  20 and 18, on the grid (`control_heights_against_design_md`). Widget text is then `text_sm`, 14px, where DESIGN.md
  says 13: the wrappers set `text_size(px(13.))`.
- **Config clamps.** A theme config caps `selection` at 30% alpha and `list_active`/`table_active` at 20%. Light's
  `accent-tint` is opaque, so the bridge writes `selection` after the config (selections paint under glyphs).
  `hover-2` is under 20% in both schemes.
- **Base colours** (`red`, `green`, ...) are private in a theme config; the bridge sets them on the theme, so a
  later `Theme::change(mode)` resets those six until the next bridge run.
- **Shadows** come from one colour (`ShadowTokens::elevations`), not DESIGN.md's per-elevation tokens with their
  1px rings. A popover or dialog that needs `shadow-raised` or `shadow-overlay` sets it in its wrapper.
- **Focus ring**: 3px at 50% of `ring`, flush outside the border (`FOCUS_RING_WIDTH`, crate-private). DESIGN.md's is
  2px solid accent at a 2px offset. Not settable; the wrappers that need the exact ring draw it themselves, fields
  turn it off (`Input::focus_bordered(false)`, `Textarea::appearance(false)`).

## D1: web content engine

**Recommendation: `gpui-webview` (wry, WKWebView) for the Artifact panel body only; HTML replies as cards with a
static snapshot; no live inline web content on `gpui-pre`. CEF is not needed for D1.**

Evidence (`src/fitcheck/webview.rs`, `fit-webview-dark.png`): a local HTML string in a 400px page placed 40px above a
520 x 220 `overflow_hidden` container, with a GPUI badge drawn after it at the same place and a GPUI row below.

- It builds on `gpui-pre` 0.3.12 with nothing installed (WebKit is a system framework).
- **GPUI cannot draw over it**: the badge is not visible. The webview is a native `NSView` added above GPUI's Metal
  layer.
- **GPUI cannot clip it**: the page shows at its full 400pt document bounds, covering the panel's label, the
  container's accent border and the GPUI row below. It hides only when entirely clipped
  (`WebView::set_geometry`).
- **Scrolling**: it follows its element's bounds every prepaint, so a webview in a scrolled list moves with it but
  covers whatever passes over it (the composer, the pills, the panel header).
- Both missing pieces exist only with `gpui-fast` (Longbridge's GPUI build with window composition surfaces,
  `enable_window_composition`), which is not `gpui-pre`: the crate's own docs say "Without it, the native view covers
  GPUI content in its bounds and extends past a container that clips it."
- The window capture includes the page (WKWebView draws within the 1.5s snapshot wait).

So: the Artifact dock's body (one rectangle, nothing GPUI over it) works; a GPUI menu, tooltip or dialog over the
panel would draw under the page, so WP-34 hides the webview while an overlay is open. Inline HTML replies (T-19)
stay cards in v1, with an offscreen snapshot (`WKWebView takeSnapshot`) as their preview. Revisit inline webviews
only if the port moves to a GPUI with window composition, or patches `gpui_macos` to host child views in a layer.

## D8: gpui-component use

**Recommendation: adopt per widget as in the table: the rich text view, selection, text area, tokens, diff,
highlighter, resizable panels and the overlay layer (popover, dialog, tooltip, menus, select, palette) wrapped; the
lists, buttons, checkboxes, slider and motion owned.** Every adopted widget goes through the bridge for colour and
through a Milagre wrapper for size, text and focus; nothing uses gpui-component's default look. Where gpui-component's
styled widget gets in the way, gpui-base offers the same behaviour unstyled (`Popover`, `Dialog`, `Tabs`,
`Checkbox`, `RadioGroup`, `Slider`, `TextSelection`), which is the next step before writing our own.

## Cost

Measured in the scratch build (release builds unstripped, Apple M5 Pro, rustc 1.99.1):

| Build                                                           | Release binary                 | Build time                                                                                                          |
| --------------------------------------------------------------- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| App (no features)                                               | 21.56 MB                       | (baseline)                                                                                                          |
| `--features fitcheck` (gallery, adopted widgets linked)         | 27.98 MB (+6.4)                | 50 s release from warm dependencies                                                                                 |
| `--features webview` (adds gpui-webview, lb-wry, objc2-web-kit) | 28.35 MB (+0.38 over fitcheck) | +38 s release, +28 s debug: the objc2 crates gain features, so the whole GPUI stack recompiles once per feature set |
| `--features fitcheck,syntect`                                   | 29.56 MB (+1.59 over fitcheck) | 35 s release, 27 s for the test build: syntect, two-face's grammars, and gpui-component again with the feature      |

The 6.4 MB is what linking the adopted widgets costs (`TextView`, `Textarea`, `Diff`, overlays); the app today
calls `gpui_component::init` but the linker drops what no view uses.

## Not tested (needs a person or more time)

- Real IME and dead keys typed on the keyboard (the tests drive the input handler's methods), trackpad scrolling and
  momentum in the text view and diff, drag-selecting with a real mouse, the cursor shapes.
- Clicking into, typing in and scrolling the webview; focus moving between it and GPUI; Retina scale changes.
- `DockArea`, `Select`, `Command`, `PopupMenu`, `Tooltip`, `Scrollbar` and `Slider` were read, not mounted.
- HTML text views, images in markdown, tables wider than the column, a 10,000-line diff, memory.
- The focus ring's look (painted outside the element; the headless platform records no pixels).
