# Public Designs and Artifact pages

This Worker publishes a snapshot of a Chat's Artifact workspace, one of its designs, a selection of its designs as a presentation, or its HTML page under one link. Sharing again, or a live link following the agent's saves, replaces that snapshot under the same link; the Worker can't tell the two apart. Sharing has no per-page design count, layer count, text or byte quota. The public page contains the design content, the page and the public title, without Chat messages, Project paths, comments or local identifiers.

A snapshot is one of four shapes, all `schemaVersion: 1`. A Designs page (no `kind`) is `{title, designs}` with at least one design; the host sends it for one design and for links from before workspaces. An Artifact page (`kind: "artifacts"`) is `{title, artifacts: [page]}` with exactly one HTML page. A workspace (`kind: "workspace"`) is `{title, designs, page?}`: the designs as in a Designs page, possibly none when the page is present, and the HTML page (`title`, `html`, `width`, `height`, `assets?`). A workspace renders with the Designs page markup (`#canvas figure`) and the page as the first frame, an `iframe.live`, or as its own block named after it once the designs use groups. A selection (`kind: "selection"`) is `{title, designs}` with 1 to 100 designs in the order the user picked them; it renders the Designs page markup without group blocks, with `#canvas[data-present]`, and the read-time viewer presents it one screen at a time (`presentation.mjs`). Deploy this Worker before a desktop release that publishes workspaces or selections: the old Worker refuses them as invalid (400). Pages have no additional publication size quota, and the normal local authoring schema still applies.

The production service is deployed at `https://share.milagre.cloud`. The host checks its health before offering publication or creating a snapshot. A localhost preview is never a public link.

## Protocol

1. The host generates 32 cryptographically random bytes. Its unpadded base64url encoding is the management secret. The page ID is the unpadded base64url encoding of SHA-256 of those **decoded bytes**. Both strings contain 43 characters.
2. After the person confirms the public publishing notice, the host sends `PUT /api/pages/<id>` with `Authorization: Bearer <secret>`, `Content-Type: application/json`, and the complete validated page snapshot. The JSON response is `{id,path:"/s/<id>"}`. A new snapshot returns 201. An identical canonical payload retried under the same capability returns 200 without spending quota. Changed content under the same capability replaces the stored page and returns 200. It replaces the previous active byte charge.
   An Artifact or workspace snapshot may name files on its page (`assets`: name, SHA-256 in hex, size, type) that its HTML shows as `assets/<name>`. Before the snapshot, the host uploads each with `PUT /api/pages/<id>/files/<sha256>`, the same authorization, its media type as `Content-Type` and its `Content-Length`: 201 when stored, 200 when the page already has it. The bucket refuses bytes that don't match their hash or length (400). A snapshot that names a file the page doesn't have returns 409 with `{missing:[...]}`. Files count toward the quota with the page's HTML (an upload past it returns 429) and are limited to 95 MB each, under Cloudflare's request body limit.
3. `GET /s/<id>` returns the read-only viewer. GET and HEAD tolerate tracking query parameters; write routes reject query parameters. The link stays available until revoked, including while the owner is offline. The response never includes the management secret or source JSON. Later edits stay private until the owner sends another PUT under the same ID.
   `GET /s/<id>/files/<sha256>` returns one of the page's files, whole or by one `Range` (a video player seeks with them).
4. `DELETE /api/pages/<id>` with the same authorization deletes the stored viewer and leaves a tombstone. It returns 204, including repeated deletes. GET returns 404 afterward. Reusing a revoked ID for PUT returns 410. Deleting a missing ID also reserves a tombstone, so a delayed upload cannot publish after cancellation. Revocation always works at quota exhaustion. A small permanent tombstone prevents delayed uploads from recreating the page; it holds no content allocation.

The secret belongs in the host's private local storage. It must never appear in a URL, renderer state, public response or logs. This is capability authorization: anyone holding the secret can revoke that one page. The public page ID does not grant management access. Losing the secret loses the ability to revoke the hosted page. Copies someone downloaded cannot be revoked.

Mutation requests with an `Origin` header are refused, including same-origin browser requests. No CORS headers or browser publishing API are provided. Custom hostnames are restricted by `PUBLIC_ORIGIN`. A local HTTP preview requires `ALLOW_LOCALHOST=true` and a loopback hostname.

## Storage and limits

A page's files (an Artifact page's or a workspace page's) are kept in the R2 bucket bound as `FILES` (`milagre-design-share-files`), under `pages/<id>/<sha256>`. Each upload is a page operation on the same allocation ledger as a publication: reserve the page's new total, store the file, commit. Public file reads check the published snapshot before streaming from R2. Replacing or revoking a page removes access to its old files immediately. The page's alarm retries deletion until R2 confirms it. An upload that no snapshot claims is removed after an hour.

Each page is a SQLite-backed Durable Object. Generated HTML is stored in 96 KiB chunks with revision metadata. A transaction replaces all chunks and metadata atomically. Public reads stream one chunk at a time, check the current revision on every pull, and stop if the link was revoked or replaced. Source JSON is discarded after validation and rendering.

The only content quota is `MAX_TOTAL_BYTES`, configured to 20 GiB for the whole service. New allocations count canonical JSON plus rendered HTML. Replacements hold the larger of the previous and new charges until their storage transaction commits, then settle to the new charge. There are no daily, per-IP, publication-count or lifetime-byte quotas. Schema validation, embedded-image restrictions, authorization and Cloudflare's physical runtime limits still apply. The normal design/Artifact authoring constraints are unchanged.

Older Workers scheduled an alarm to expire each page after 30 days. The current Worker ignores those deadlines and keeps existing published links. Pages whose content was already deleted stay tombstoned. Both clients can publish a fresh link for a tombstoned page through the shared host.

Quota uses a durable per-page allocation ledger. A page saves a pending operation and schedules a retry alarm before reserving bytes. Monotonic operation numbers fence delayed requests. Commit and abort are idempotent. Interrupted writes abort their reservation; committed writes settle it. Revocation saves a tombstone and a refund intent locally. After file cleanup, the alarm releases the allocation, including any interrupted reservation. Public reads and revocation work while the quota service is unavailable. A failed cleanup keeps its allocation until the refund completes. Tombstones retain no content charge. They and the ledger have small metadata storage costs outside the content cap.

### Upgrade existing hosted pages

The old lifetime counter cannot identify active pages or recover discarded source JSON. When that counter exists, new uploads are blocked until a one-time inventory completes. Reads and revocations continue. Inventory charges legacy pages for their surviving HTML and preserves their links. Subsequent publications use canonical JSON plus HTML. If existing content is already over the cap, uploads stay blocked until enough space is reclaimed.

1. Deploy this Worker with a temporary, random `MIGRATION_TOKEN` secret. Keep the token out of command arguments, logs and commits. The maintenance routes return 404 when this secret is absent.
2. Load the Cloudflare account/token environment and set `SHARE_PAGES_NAMESPACE_ID` to this Worker's `DesignPage` namespace ID. Set the same `MIGRATION_TOKEN` in the script environment. The Cloudflare token needs read access to Durable Object namespaces and objects.
3. Run `node apps/design-share/scripts/migrate-active-quota.mjs` from the repo root. It inventories every stored object and enables uploads only after all imports succeed. Failures leave uploads blocked; rerunning is safe. `SHARE_ORIGIN` optionally selects another HTTPS deployment.
4. Remove the Worker's temporary `MIGRATION_TOKEN` secret after success. Fresh services without the legacy counter need no inventory.

The operator-only inventory is never exposed to clients. Application quotas bound accepted content, not request traffic or rendering CPU. Configure Cloudflare ingress controls separately if needed.

## Link previews

Public GET responses include Open Graph and Twitter card metadata, read by preview bots that ignore robots.txt: the published title, a description of the page, the canonical snapshot URL without tracking parameters, and a branded 1200 × 630 PNG at `/og.png`. The image is bundled into the Worker and contains no snapshot or Chat content. Regenerate it with `node scripts/share-og.cjs`.

The description is fixed at publication and stored in the page's own `<meta name="description">`, at most 200 characters. An Artifact uses its own meta description, or else its visible text with scripts, styles and a repeated title removed. A Designs page lists its design names, or for a single design the text of its visible layers. A workspace gives its page's text, then its design names. Its title keeps the `| Milagre Designs` suffix. Pages published before descriptions existed, and pages with no text, keep a generic line.

Metadata is inserted into the first streamed HTML chunk at read time, so existing links receive it without changing their stored snapshot or capability. Original bytes are preserved across UTF-8 chunk boundaries. Revoked pages still return 404 without preview metadata. Sharing apps may retain an earlier preview in their own cache after a deployment or revocation.

## Viewer security

The shared renderer generates HTML from validated structured documents: the frames and a static fallback layout, with no script. The service adds the viewer (`src/viewer.mjs`) to the head of every page when it is read, so a viewer change reaches every link, including pages published before it; stored bytes never change. The viewer replaces whatever layout and chrome an older page carried. A public page has no header or footer: the canvas, or the Artifact's frame, fills the window. Designs pages lay their frames out as the desktop Canvas does: one row, or once any design names a group, one named block per group stacked down the page, with a zoom bar (zoom out, the zoom reading that resets to 100%, zoom in, Fit) and a Milagre logo that links to milagre.cloud; Artifact pages get the logo alone. Dragging pans and never selects text; pinch, Ctrl/⌘-scroll or the keys `+`, `-`, `0` (fit) and `1` (100%) zoom; double-click zooms to a frame or back to everything. An interactive design ignores the pointer until it is clicked, so a drag across it still pans; a click outside or Done hands the pointer back. Right-click, a frame's ⋯ button or a long press on a phone opens its menu: Download PNG (twice the frame size, capped at 16 megapixels), Download SVG, Copy image, Zoom to frame and Copy link to frame (`#frame=<slug>`, which opens zoomed to that frame); an interactive design offers Interact and Download HTML instead. The viewer runs in browsers from its functions' source, so it uses only browser globals and `wrangler.toml` sets `keep_names = false`. External image URLs are refused; the host embeds supported raster assets before upload. The page CSP permits embedded images, inline styles and the inline viewer, with no external network access, forms, framing or base URL changes. Responses disable caching and referrers and request search engines not index the page. `/robots.txt` disallows every path for every crawler. Link preview bots that honor it (Slack, Twitter/X, LinkedIn) unfurl a bare URL; Discord and Facebook ignore it and still show the preview. `noindex` is a crawler preference, not an access control. Anyone with a public URL can read or redistribute its content.

Public HTML Artifacts run inside an opaque `srcdoc` iframe with only `allow-scripts`. The wrapper's HTTP CSP is inherited: inline interaction is allowed, remote resources and nested frames are blocked, and the sandbox denies access to the parent origin, cookies, storage, forms, popups, downloads and top navigation. `frame-src 'none'` blocks self navigation while permitting the initial inline document. Escaped titles and `srcdoc` attributes keep arbitrary Artifact source inside the frame. The host does not fetch or embed external resources for Artifacts, so shared pages must be self-contained: the files a page shows are uploaded with it, and its policy lets it load images, media and fonts from this origin only. Files are served with `Content-Security-Policy: default-src 'none'; sandbox` and `nosniff`, and anything but images, video, audio, fonts, plain text and PDF as a download, so a file never runs as a page of this origin. The full HTML source and every file it names, including hidden content, are public.

## Check and preview

```sh
node --test apps/design-share/src/*.test.mjs
npx tsc --noEmit -p apps/design-share/tsconfig.json
cd apps/design-share
npx -y wrangler@4.147.0 dev --local-upstream localhost --var ALLOW_LOCALHOST:true
```

The local preview uses local Durable Object and R2 storage. It does not upload snapshots or files to Cloudflare. Before the first deployment with files, create the bucket once: `npx -y wrangler@4.147.0 r2 bucket create milagre-design-share-files`. Production deployment uses the private Cloudflare environment described in the repository instructions; do not copy credentials into this app.

Cloudflare references: [SQLite-backed storage](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/) and [Durable Object limits](https://developers.cloudflare.com/durable-objects/platform/limits/).
