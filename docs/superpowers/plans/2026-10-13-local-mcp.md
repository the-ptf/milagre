# Local Milagre MCP Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans. The accepted delegation authorizes continuous implementation; the originating Chat reviews the resulting diff.

**Goal:** Expose scoped local Project, Worktree, Chat and separately supplied Designs tools through the owning host.

**Architecture:** A persisted grant store and revision-aware registry feed a loopback-only HTTP endpoint. Named adapters reuse host operations; a durable operation journal prevents blind replay after interruptions.

**Tech Stack:** Node HTTP, existing Zod, React and existing React Native controls. No native dependencies.

**Spec:** Accepted integration contract in this Chat's delegation, October 13, 2026.

## Global Constraints

- No second host, generic RPC tool, network exposure, deployment, release, PR or merge.
- Explicit groups, capabilities and Project scopes. Design scope binds one Chat and selected design IDs.
- Credentials appear only on creation/rotation. Grant edits, expiry and revocation invalidate cached tools.
- Preserve Worktree setup, host events and permission modes. Mutations require durable request IDs.
- Desktop and mobile configuration stay in sync. Designs implementation belongs to the linked Chat.

## Review Focus

- Grant edit during awaited tool execution must invalidate the old revision.
- Restart after mutation but before response must never replay an uncertain mutation.
- Lists and returned state must not reveal Projects or Chats outside the grant.
- Loopback binding alone is insufficient: reject hostile Host/Origin and invalid credentials.
- Connection and permission modes cannot be widened by tool arguments.
