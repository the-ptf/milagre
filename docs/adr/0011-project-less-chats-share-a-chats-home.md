# Chats without a Project share a Chats home

A Chat started with No project (spec `docs/superpowers/specs/2026-10-28-project-less-chats-design.md`) is an ordinary Chat in an ordinary Project, so sessions, resume, `chats.db` (ADR-0007), idle unloading (ADR-0009), account routing, approvals and Terminals work there unchanged. That Project is the **Chats home**: one internal Git repository per computer at `~/.milagre/chats` (`packages/core/src/chats-home.cjs`), made on first use with one empty commit under its own identity, "Milagre". Each project-less Chat is a Chat in it on its own Milagre Worktree, `~/.milagre/worktrees/chats/<slug>`, with isolation always `worktree`. Archiving it removes that Worktree through the archive flow as it is: removed when clean, deleted with the usual warning when the agent wrote files.

- **Two commands.** `chats:home` returns `{ path, exists }` and changes nothing. `chats:ensure` creates the home if it is missing and opens it, without adding it to the recent list, without registering it and without changing the Project a window shows. Desktop and phone call it when No project is picked, then start the Chat in the returned path as in any Project.
- **Left out of every list, daemon-side.** `project:recent`, `project:registry`, the Milagre MCP `project_list` and the onboarding lists never carry the home. A client of any age therefore shows no Project named "chats". Clients need no filter and no flag on those entries.
- **Kept in the snapshot.** The daemon snapshot still has the home, marked `kind: "chats"`, because windows restore their Chats from it. Phones don't read the snapshot's Projects.
- **Named "No project".** `projectName` returns "No project" for the home, so the inbox, notices and notifications say so instead of "chats".
- **Gates accept it explicitly.** The home is not in the registry, so `project:read` and `project:switch` accept it by name, and so do the MCP tools and Routines, each through an explicit home entry. A window that opens a project-less Chat shows the home but never remembers it as the last Project.
- **One account selection.** All project-less Chats on a computer share the home's account selection, a "Chats without a Project" row in Settings › Accounts.
- **Considered and rejected:** a hidden Project per Chat in the data directory, like bot homes (ADR-0010): the registry, the recent list, `project:read`, `project:switch` and the phone's lists all skip hidden homes, so the phone would never see these Chats. A plain-folder (`git:false`) Project: it can't hold more than one Worktree, so it can't be shared. List entries flagged `kind: "chats"` for clients to filter: a phone on the previous OTA would show a Project named "chats".

## Computers without Git

The original Git-only home blocked Skip on a clean Windows installation. When the Git executable is absent on first use, the home instead writes `.milagre-folder-chats` and creates one directory per Chat under `.chat-folders`. These directories are discovered and restored as the home's Worktrees without Git commands. The marker preserves this mode after restart or a later Git install; no automatic conversion changes existing Chat folders. Archiving hides these Chats and retains their files, since no Git status can prove deletion safe. Existing Git homes and damaged Git checkouts never fall back to this mode. Both desktop and mobile still create an isolated folder for every new Chat and hide Git controls for the home.
