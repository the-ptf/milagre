# Chat edit scope

Open **Edit scope** by the Chat composer on desktop or phone. For each owned Worktree, enter allowed files or directories and protected paths, one relative path per line. A directory includes its descendants; `.` names the entire Worktree. Protected paths win. An empty allowed list permits no edits. An unset scope leaves the existing permissions unchanged.

Save or remove a scope while the Chat and its background work are idle. The host freezes the active policy for a turn and its background work. Steering does not change it. An agent can use `edit_scope_read` and `edit_scope_request` to propose complete revised lists, with a reason. The user reviews every proposed path, including removed protections, and approves or declines in the same desktop/phone panel. Approval during a turn waits for a new turn. Newer requests replace older pending requests; stale approvals and stale saves fail.

Claude's file-edit PreToolUse hook denies out-of-scope edits even in Full mode. Codex and ACP deny file-edit approval requests that reach Milagre. Commands, provider operations that bypass those callbacks and background writes use host observation. Scope checks add restrictions; they do not grant permissions or override existing workspace, permission mode, Bot or babysit rules. Provider subagents inherit the Chat's host checks when their calls pass through those hooks; execution advisors use their parent's frozen policy and observer.

Observation compares file content fingerprints, modes and symlink targets before work, periodically during work and after it ends, including failed or stopped turns. It checks Git-tracked and nonignored files, plus explicitly protected ignored paths. Existing dirty files are fingerprinted too. Contents are never saved in the scope store. A content change committed during work still differs from the initial content. Renames are observed as a deletion and addition. Warnings name observed changes, without claiming which writer made them; nothing is reverted automatically.

This is not OS filesystem confinement. External files, ignored files outside protected paths, transient writes reverted between samples and unobservable provider operations can escape observation. Captures are bounded to 20,000 entries, 16 MiB per file and 128 MiB overall. Capture failures, unavailable files, size limits and interrupted monitoring produce explicit incomplete-observation warnings. macOS protected-path matching conservatively ignores case. Symlink resolution and owned-root checks prevent an intercepted edit from using a path alias to escape its policy; arbitrary commands have no equivalent pre-write guarantee.

Policies, pending requests, approved next-turn policies and warnings live locally in the host profile's `edit-scopes.json`. Scope changes use revisions and atomic writes. Reconnecting clients read that host state; a host restart reports interrupted observation and starts a new baseline on the next turn. Scope rules and requests do not travel through generic Chat patches or an agent approval tool. A process already running with unrestricted filesystem access can still modify local data; edit scope does not replace that process's sandbox.
